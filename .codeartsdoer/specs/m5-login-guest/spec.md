# 词力战士 M5 阶段需求规格：微信登录注册 + 游客限制 + 资料完善

> 文档状态：M5 需求规格（v1.0，已确认方向）
> 关联文档：`design.md`（技术设计）、`core-gameplay/spec.md`（M1）
> 已确认决策：标准登录 wx.login+code2session+token；手机号仅预留；范围 P1~P4。

---

## 一、背景与目标

当前小程序**无登录/注册能力**：openid 靠云托管网关注入（前端拿不到），昵称纯本地存储，关卡解锁纯本地推导，用户维度后端接口（成绩/形象/排行/错题/签到/成就）无法绑定真实用户。产品诉求：

1. 支持**微信注册（登录即注册）**：wx.login 静默建档，openid 唯一标识；
2. **昵称需在登录/注册后设置**并云端持久化（首登引导完善资料）；
3. **未登录游客仅可玩第 1 关**，其余关卡与用户功能不可见/锁定；
4. 补齐合规与体验项（隐私协议、分享、退出登录等）。

## 二、功能需求

### REQ-LOGIN-1 静默登录（P1）
当小程序启动时，系统**必须**尝试 wx.login 换取 code 并调用后端登录接口完成建档/登录；失败时**必须**静默降级为游客，不阻塞主流程。
- 验收：启动后无感登录；断网/未配置时仍可进入首页并试玩第 1 关。

### REQ-LOGIN-2 登录态管理（P1）
系统**必须**持久化登录令牌（本地 token），并在请求中自动附带；令牌失效时按匿名降级处理。
- 验收：重启小程序登录态保持；多设备重登后旧令牌失效。

### REQ-LOGIN-3 注册完成判定（P1/P3）
系统**必须**以「openid 建档 + 昵称已设置」作为注册完成（needProfile=false）判定。
- 验收：新用户返回 needProfile=true 并引导设置昵称。

### REQ-GUEST-1 游客关卡限制（P2）
当用户未登录时，系统**必须**仅开放第 1 关；第 2+ 关显示锁定，点击**必须**引导登录而非进入。
- 验收：未登录关卡页仅第 1 关可进入，其余点按出现登录引导。

### REQ-GUEST-2 游客功能入口拦截（P2）
当用户未登录点击形象/排行/错题/签到/成就等用户维度入口时，系统**必须**弹出登录引导（确认后可静默登录并继续/或跳资料完善）。
- 验收：各受限入口未登录均出现登录引导。

### REQ-PROFILE-1 昵称云端化（P3）
当用户登录后，昵称**必须**写入后端 users.nickname 并回显；本地仅作缓存。
- 验收：设置昵称后排行榜显示真实昵称；换设备登录可见同一昵称。

### REQ-PROFILE-2 首次注册引导（P3）
当 needProfile=true 时，系统**必须**在登录成功后引导用户进入昵称设置页。
- 验收：新用户登录后自动引导设昵称；可跳过但受限功能不解除。

### REQ-COMPLY-1 协议同意（P3）
首次进入小程序时，系统**必须**展示用户协议与隐私政策并取得同意（本地持久化），拒绝则不收集个人信息但可试玩。
- 验收：首次弹出协议，同意后不再弹；未同意不触发登录。

### REQ-ENH-1 分享/退出/云同步（P4）
系统**应当**支持页面分享、退出登录；登录后星级等进度**应当**同步至账号。
- 验收：分享可用；退出后游客态生效。

## 三、范围边界（本期不做）

- 手机号绑定流程（字段/接口预留，需企业认证后可开）；
- 头像上传至云存储（本期存本地临时路径）；
- 多端并行登录（单 token 顶号模型）。

## 四、验收总览（P1~P4）

见 `tasks.md` 各任务验收；核心链路验收：**游客仅第 1 关 → 登录（静默建档）→ 引导设昵称 → 全部关卡与功能可用 → 昵称/进度云端可见**。
