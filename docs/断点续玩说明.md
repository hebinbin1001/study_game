# 数字智力 · 断点续玩说明

> 2026-10-18 落地。解决「闯关途中不小心退出，再进来只能从头开始」。
> 代码：`miniprogram/utils/puzzle-resume.js` + 七个玩法页面。

## 一、为什么要做

数字智力类玩法一局耗时几分钟到十几分钟：

| 玩法 | 典型一局 | 原来退出后的后果 |
|---|---|---|
| 华容道 | 30~120 步 | 全部白走 |
| 数独（9×9） | 5~15 分钟 | 题面重新随机，等于换了一道题 |
| 迷宫 | 30~80 步 + 若干道题 | 地图重随机，答过的门记录清零 |
| 2048 | 几十到几百步 | 棋盘清零 |
| 24 点 / 一笔画 / 汉诺塔 | 十几步到几十步 | 从头再来 |

触发场景很日常：切到微信聊天、接电话、被系统回收、误触左上角返回。

## 二、机制

统一模块 `utils/puzzle-resume.js`，**每个玩法一个槽位**（`ww_resume_<game>`），只保留「最近一局未完成」。

```js
{ v: 1, game: 'klotski', level: 3, ts: 1730000000000, state: { ... } }
```

| 字段 | 作用 |
|---|---|
| `v` | 结构版本。页面 state 结构改了就把 `VERSION` +1，旧快照自动作废，不会读出脏局面 |
| `level` | 关卡号。带 `?level=N` 进入时只恢复同一关；用户点别的关不抢（旧档保留） |
| `ts` | 写入时间。超过 **7 天**自动作废并清除 |
| `state` | 各玩法自己的「最小可恢复状态」，模块不解释 |

接口：`save(game, level, state)` / `load(game)` / `loadFor(game, level)` / `clear(game)` / `has(game)` / `levelOf(game)`。

保护措施：

- 序列化后超过 **64KB** 直接拒写并清旧档（不能挤占星级等关键存档的配额）；
- `JSON.stringify` 抛错（循环引用等）返回 `false`，不把页面带崩；
- 页面恢复前做**结构校验**，脏数据一律 `clear` 后回退到正常开局。

## 三、各玩法的存档内容

| 玩法 | `state` 内容 | 写入时机 | 清除时机 |
|---|---|---|---|
| 华容道 `klotski` | `pieces[{glyph,x,y,w,h,name,kind}]`、`moves`、`demoUsed` | 每走一步 / 撤销 / `onHide`·`onUnload` | 通关、重开、换关 |
| 数独 `sudoku` | `n`、`puzzle`、`answer`、`values`、`lives`、`mistakes`、`doneCells` | 每次填字成功 / 扣命 / 生命周期 | 通关、生命耗尽、换关 |
| 2048 `g2048` | `board[16]`、`score`、`usedSteps`、`maxTile`、`elapsedMs` | 每滑一步 / 生命周期 | 通关、死局、重开 |
| 24 点 `math24` | `tiles[{id,frac,text,sel}]`、`steps`、`tileId`、`history`（最近 5 步）、`deadEnd` | 每次合并 / 撤销 / 生命周期 | 通关、重开 |
| 一笔画 `one-stroke` | `li`、`path`、`used`、`steps`、`hintLeft`、`hints` | 每接一个点 / 撤销 / 生命周期 | 通关、重来、换关 |
| 迷宫 `maze` | `lv`、**`seed`**、`pos`、`steps`、`lives`、`gateState`、`chestOpen`、`qs`、`visited` | 每走一格 / 答题结果落定 / 生命周期 | 到出口、生命耗尽、重开 |
| 汉诺塔 `hanoi` | `state`（三柱盘面）、`steps` | 每移一步 / 撤销 / 生命周期 | 通关、重置 |

### 三个关键点（踩过的坑）

1. **随机内容必须连种子一起存**：迷宫是 `gen(level, seed)` 生成的，只存坐标会导致
   「同一个格子换了一张图」；数独题面每次 `generate()` 都不同，必须把题面与答案整份存下来。
2. **不能只存「看起来够了」的字段**：数独的剩余生命、一笔画的剩余提示次数，不存就等于
   「退出可以回满血 / 刷提示」。
3. **通关必须清档**：否则下次进页面会被「已完成的一局」顶掉，玩家开局就是结算界面。

## 四、恢复时的表现

进入页面若无提示地直接恢复，用户会以为「怎么在这」——所以恢复后弹一条 toast：

```
已恢复上次进度 · 第 3 关 · 27 步
```

棋盘/盘面直接显示恢复后的局面，玩家可以立刻继续操作；顶部原有的「重新开始 / 重来」按钮照常可用（会清档）。

## 五、扩展新玩法怎么做

1. 页面 `require('../../utils/puzzle-resume')`，定义 `var PAGE = '<玩法 key>'`（与星级 key 一致）；
2. 写 `_saveProgress()`：只存「恢复所需的最小状态」，可 JSON 序列化；
3. 写 `_restore(snap)`：先校验结构（越界/重复/缺字段 → `clear` 并 `return false`），
   再还原内部字段与 `data`，最后重绘 + toast；
4. `onLoad` 里：`var snap = resume.load(PAGE); if (snap && (!want || snap.level === want) && this._restore(snap)) return;`
5. 开局函数（`start` / `startLevel` / `restart`）第一行 `resume.clear(PAGE)`；
6. 结算函数（`_win` / `_finish` / `_lose`）第一行 `resume.clear(PAGE)`；
7. `onHide` / `onUnload` 兜底 `this._saveProgress()`；
8. 在 `tests/unit/puzzle-resume-pages.test.js` 的 `GAMES` 里加上该玩法（源码护栏会自动要求三件套）。

页面级往返断言的重点：华容道「棋子逐一对上、不叠子」、2048「棋盘完全一致」、
迷宫「重建的墙与存档时逐格一致」、数独「答案原样恢复」、一笔画「提示次数不回满」。

## 七、已知边界

- **真机端到端未跑**：微信开发者工具自动化端口在本机起不来（CLI 拉起依赖的 `reg.exe` 被安全策略拦截），
  上述结论来自单测 + 静态检查；工具恢复后建议补一条「走两步 → 返回 → 重进 → 步数还在」的真机用例。
- 撤销栈只有华容道/24 点/汉诺塔有，且**不进存档**（恢复后不可撤销）：把整条历史塞进存储不划算，
  玩家重新攒一步即可。
- 街机类玩法（贪吃蛇 / 弹球 / 连连看 / 2048 挑战）不做断点：一局以秒计，恢复残局反而奇怪。
