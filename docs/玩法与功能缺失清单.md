# 玩法与功能缺失清单（2026-10-28）

> 视角：只找「**本来该有、但现在没有**」的东西。已知的结构性问题（Lv 与段位重复、玩法线关卡重叠、组件接入不一致、休闲玩法占比）见 `全量检查报告-架构玩法布局.md`，本文不重复。
>
> 盘点范围：4 个 Tab、49 个页面、22 款玩法、8 种题型、35 个 utils、20 张表、2423 条词库。

---

## 摘要

项目的能力密度其实很高：异步 PK、每日挑战、双月赛季、签到里程碑、成就、错题本 + 艾宾浩斯、自建关卡、题库编辑、皮肤、排行榜，一个都不缺；干扰项生成还专门做了汉字形近字表和英语形近字母对。

但有三件事**完全不存在**，而且都是用户第一天就会撞上的：

1. **没有声音** —— 全站发音 100% 失效（`app.json` 从未声明插件），也没有「点一下听单词」的入口；
2. **没有「学」** —— 全站没有单词卡、预习、词表浏览。玩家第一次见 `comfortable` 就是 `c_ _f_rtable`；
3. **没有召回** —— 零订阅消息。复习提醒、断档预警、赛季结算，一个都没有。

下面按「内容 → 闭环 → 玩法 → 留存 → 裂变 → 体验」六层列，每条给出证据、缺什么、建议做法、改动量级。

## 一、内容层：地基比想象中薄

### 1.1 全站发音失效（P0，改动量级：小）

**证据链完整，可以复现：**

| 位置 | 现状 |
|---|---|
| `miniprogram/app.json` | 顶层键只有 `pages / subPackages / preloadRule / window / tabBar / sitemapLocation / usingComponents / lazyCodeLoading` —— **没有 `plugins`** |
| `miniprogram/game/audio.js:31-39` | `getTTS()` 里 `requirePlugin('WechatSI')`，未声明插件必然抛错 → `catch` 返回 `null` |
| `miniprogram/game/audio.js:58-62` | `speak()` 里 `if (!tts) return;` —— 静默降级，连日志都没有 |
| 调用点（仅 3 处） | `pkg-games/game/game.js:433`、`pkg-games/letter-bubble/letter-bubble.js:441`、`pages/wrong-review/wrong-review.js:295` |

所以这 3 处**从来没响过**，而且因为静默降级，开发者工具里也不会报错。

更进一步：全站没有「🔊 点击发音」的 UI。`ipa` 音标只在 3 个页面显示（`game`、`letter-bubble`、`bank`），另外 19 个玩法连音标都没有。一个背单词产品，玩家无法知道单词怎么读。

### 1.1 处置结论：**2026-10-28 决定暂停，不做**（结论存档，避免重复调研）

**已完成的部分**：`game/audio.js` 的 `getTTS()` 已加一次性 `console.warn`，这个洞不会再被瞒住；
预习卡的喇叭按钮也已接好，插件可用时自动生效、不可用时给 toast 而不是没反应。这两处保留。

**为什么暂停**：微信「同声传译」插件在**当前小程序主体/类目下搜不到**（微信开放社区口径：搜不到即主体不支持），
而备选方案要动支付/资源，用户决定先不动。详见下面的三条路对比。

**三条路实测结论**（2026-10-28 核过官方文档 + 实测后端）：

| 方案 | 可行性 | 成本 | 结论 |
|---|---|---|---|
| WechatSI 插件 | 需绕过三个入口：① 先写 `app.json` 声明让编译报错→点报错里的「添加」② 插件文档页顶部「添加插件」③ `fuwu.weixin.qq.com` 服务市场搜索添加 | 免费，但**语音合成上限 2 万次/天**（约 2000 DAU 就打满），且返回的是 **3 小时有效临时链接**、必须联网 | 可作短期兜底，不能撑拉量 |
| 云存储预生成 | 可行。`innerAudioContext` 的**网络音频必须配 downloadFile 白名单**，而云托管裸域名未备案配不进去；云存储 fileID 免白名单（基础库 2.2.3+） | 1765 词 ≈ 10MB 存储；做本地缓存后每词一生只下一次 → 增量可忽略（和云托管同一套资源点账单） | **长期正解**，但需要 TTS 音源 + 上传流程 |
| 第三方直连（有道/百度 TTS） | 可行，域名可加 downloadFile 白名单 | 免费，但无 SLA、可能限流、中文成语支持差 | 仅适合开发期听个响，不上线 |

**恢复时要做的**（按顺序，不需要改前端架构）：
1. 定 TTS 音源：腾讯云语音合成（约 1~2 元生成全量，商用授权干净）或 edge-tts（免费、授权灰区）；
2. `tools/audio/` 生成全量 mp3 → 传云存储 → 输出 fileID 清单；
3. `utils/word-audio.js` 做三级音源（本地缓存 → fileID → 插件兜底），接进 `audio.js` 的 `speak()`；
4. 在 `game.wxml` 音标旁加喇叭按钮，`settle-pop` 错题卡逐词朗读。

**注意**：恢复前先确认云托管还在跑（`curl https://express-g0hk-.../api/health` 应返回 `db:connected`）。
2026-10-28 实测后端正常，但免费额度已到期转按量计费 —— 实例常驻是主要成本，建议把「最小实例数」设为 0。

### 1.2 例句 0 条，而代码以为有（P1，量级：中）

全库 2423 条，出现过的字段只有：`type / q / a / hint / py / ipa(1851) / book(753) / d(58)`。

- **`ex`（例句）0 条**，但 `pkg-games/result/result.js:47` 的注释写着「ex 字段词库已支持，这里顺手用上」，`:61` 还老老实实 `ex: it.ex || ''` —— 渲染位一直空着；
- `fill`（英语句子填空）130 条是唯一带语境的题型，占 **5.4%**；
- `py` 字段等于单词本身（如 `beautiful` 的 `py` 就是 `beautiful`），是无效占位。

**后果**：玩家学到的是「中文 ↔ 拼写」的配对，不是词的用法。这恰好是「打怪学词」最该补的。

**建议**：不必全库补。先补 **300 个高频词**（kg~g6 的 w1 词条里挑），灌进 `ex`，在结算错题卡、预习卡、`bank` 页展示。`tools/dict/` 已有审计脚本，加一个注入脚本即可。

### 1.3 词量撑不起「教材同步」这个承诺（P1，量级：大 / 或改表述）

| 指标 | 实际值 |
|---|---|
| 词库总条目 | 2423 |
| 去重后单词数 | **1765** |
| 单年级条目 | 100（kg）~ 253（g3） |
| 带教材版本标记 | 753 条（pep 405 + wys 348，仅小学 6 年级） |

人教 PEP 单年级上下册通常 250~400 词。也就是说**选了「人教版三年级」，实际可出的版本词只有百来条**，几关就滚完一遍。

**两条路，选一条**（见文末待拍板 4）：
- A. 补词库到「每册对齐」——纯内容工程，量级大；
- B. 把表述从「教材同步」降级为「课标高频词 · 按年级分级」，`me.js:204` 与 `constants.js:44` 的文案一起改，量级小。

### 1.4 题型结构偏科：63% 在练拼写（P2，量级：小）

| 题型 | 条数 | 占比 | 实际考什么 |
|---|---|---|---|
| w1 挖 1 格 | 1534 | 63.4% | 拼写记忆 |
| c2 汉字挖多字 | 380 | 15.7% | 拼写记忆 |
| fill 句子填空 | 130 | 5.4% | 语境 |
| trans 中英互译 | 105 | **4.3%** | 词义理解 |
| w2 挖多格 | 95 | 3.9% | 拼写记忆 |
| c1 汉字挖 1 字 | 92 | 3.8% | 拼写记忆 |
| d 干扰项干扰 | 58 | 2.4% | — |
| zc 组词 | 58 | 2.4% | 词义 |
| xhy 歇后语 | 29 | 1.2% | 语文常识 |

**真正考「词义理解」的 trans 只有 4.3%**，剩下大半是在练「看中文回忆拼写」。

**建议（不用等补数据）**：`hint` 字段 100% 覆盖，可以**现场造题** —— 由 `hint` 反向生成「看中文选英文」和「看英文选中文」，把 trans 的有效供给从 105 条放大到 1765 条。改的是题干采样权重 + 一个 `trans` 动态构造分支。

### 1.5 综合关卡把英语词和语文成语混在一起出（P1，量级：中，需确认是否有意）

用 g3（三年级）主线第 1 关的真实抽取结果验证预习卡时撞见的：

```
camera(照相机) / 姐妹 sister / white(白色) / together(一起)
目不暇接 / 黔驴技穷 / 赏心悦目 / 伯牙绝弦 / 三心二意 / 多姿多彩
```

- 一个定位「英语单词」的产品里，同一关混着 4 个英语词和 6 个语文成语；
- 「伯牙绝弦」是六年级课文，现在和三年级英语同屏；「黔驴技穷」「杯水车薪」也在 g3 池里。

之前这件事藏在「打着打着觉得有点怪」里，加上预习卡后会直接摊在玩家面前。

**需要你确认**：这是有意做「语数英混合」还是词库分配时按词频批量塞的？
如果是后者，建议审一遍成语的年级归属（`miniprogram/data/g*.js` 里 c1/c2/xhy 条目），
并按学科给关卡分线（英语线 / 语文线），而不是混抽。

## 二、学习闭环：缺了「学」和「测」

现有链路是 **练（22 玩法）→ 记（错题本）→ 复习（艾宾浩斯）**，两头都空着。

### 2.1 没有「学」（P0，量级：中）

- `pages/` 与 `pkg-games/` 里没有 `learn / cards / word-list` 任何一类页面；
- 学习 Tab 的六张卡全是**报告类**：正确率、待复习、每日一题签到、签到日历、题库、自建关卡、错题；
- 玩家第一次遇到 `comfortable`，直接就是 `c_ _f_rtable` 挖空题 —— 没学过就考。

**建议**：关卡开局插一张 **15 秒「本关 10 词」速览卡**（词 + 音标 + 🔊 + 释义，可一键跳过）。样式可直接复用 `result` 页的错题卡。这样「学」不占用独立入口，也不会把碎片场景变重。

### 2.2 没有水平测试 / 定级（P1，量级：小~中）

新用户第一次进来要自己选年级，选错了要么太简单、要么全错。全站没有「测一下你适合几年级」。

**建议**：纯本地 10 题（kg / g3 / g5 / g7 / g9 各抽 2 题），按正确率推荐年级并直接写入设置。顺带产出一张「初始诊断」卡片，天然带分享欲（见 5.1）。不用后端。

### 2.3 复习只覆盖「错题」，答对但没记牢的词没人管（P1，量级：中）

`utils/review.js` 的池子来自 `WrongRecord`（注释写得很清楚：「错题回流主玩法」）。`ebbinghaus.js` 只服务错题。

结果：一个词答对一次就永久消失，没有「1/2/4/7/15/30 天后再见一面」的机制 —— 而这才是间隔重复的价值所在。

**建议**：复习池纳入「答对但用时超过阈值」「历史连错过 2 次以上」的词；或给 `mastery` 加时间衰减，让答对过的词在 7 天后重新进入待复习。

### 2.4 没有生词本 / 收藏（P2，量级：中）

只有**被动**错题本。没有「这个词我想再看一眼」。`pages/bank` 是题库编辑（改数据），不是学习收藏。

**建议**：错题卡、结算卡、预习卡上加「⭐ 收进生词本」；独立列表 + 「用生词本组一局」（可复用 `level-editor` 的组关能力）。

## 三、玩法层：22 款，都是「读」和「写」

### 3.1 没有听力玩法，也没有听力题型（P1，量级：小，前提是 1.1 先修）

8 种题型（`utils/constants.js:85-94`）全部是「看字 → 选/填」，没有一条走耳朵。22 款玩法同样没有。

英语四大能力（听说读写），现在只覆盖「读」和「拼写」。

**最低成本做法**：新增 `type: 'listen'` —— **听音选义**（TTS 读单词，4 个中文选项），完全复用现成 `question.js` 管线（干扰项从同年级 `hint` 抽），只需加一个题型分支 + 一个采样权重。成本比做新玩法低一个量级。

### 3.2 没有口语跟读（P2，量级：大）

无录音、无评测。需要「智聆口语测评」类插件，建议后置。

### 3.3 没有显式的「复习关」（P1，量级：小）

错题回流是 `review.js:26` 的 `DEFAULT_REVIEW_RATE = 0.25` —— **以 25% 概率隐式插入对局**。玩家感知不到「我在复习」，也不知道「今天有几个词到期」。

**建议**：首页 / 学习 Tab 加一行「**今日复习 8 词 →**」，点进去用错题组一关（直接调 `review.buildPool({dueOnly:true})`），结算页明说「这 8 个词你昨天错了」。这是把已有的底层能力变成可见功能，性价比最高的一条。

### 3.4 同一关题目恒定（P2，量级：小）

`utils/challenge.js:293`：`seedOf = hash('challenge:grade:level')` —— 同一关每次进去题目**完全一致**。

配合「单年级只有 150 词」，刷星时内容 100% 重复，玩家会觉得「这关我背下来了」。

**建议**：保留种子（PK / 每日挑战需要同一套题），但给「重复挑战」加一个 attempt 计数进种子 —— 第 2 次起换一组题，星级仍按最好成绩。

### 3.5 没有短期活动（P2，量级：小~中）

赛季是双月榜（`pages/season`），周期太长。没有「周末双倍星」「节日限定关」「限时 Boss」这类短期刺激。

### 3.6 社交只有「战帖」，没有「关系」（P2，量级：中）

`server/pk-rules.js` 的设计很清醒（异步战帖而非实时对战）。但：

- 没有好友列表；
- 没有班级 / 组队；
- 战帖打完就断，没有「最近对手 → 再战」。

**建议**：先做「最近 3 个对手 + 一键再战」，成本低、复用现有 pk 接口。班级需要老师端，明确后置。

## 四、留存 / 召回：最弱的一环

### 4.1 订阅消息：基础设施已就位，等模板 ID（P0，量级：中）

**2026-10-28 已接入**（操作步骤见 `docs/订阅消息接入指南.md`）：

- 服务端：`sendSubscribe`（云托管内网免 token，失败回落公网 https + access_token）、场景表 `server/subscribe.js`、`subscribe_grants` 记账表（**启动自动建**，不用手工跑 SQL）；
- 端上：`utils/subscribe.js`（预热配置 + 弹窗 + 结果判定）、PK 页「🔔 好友应战时提醒我」按钮；
- 首个场景 `pk_accept`：战帖被应战时通知发起人，**事件驱动，不需要定时器**。

**现在只缺一样东西**：公众平台申请模板 ID → 配到云托管环境变量 `WX_TPL_PK_ACCEPT`。
没配之前按钮不渲染、发送直接跳过（1ms 返回），不会留下「点了没反应」的半成品。

其余三个场景等这个跑通再排：

| 场景 | 触发时机 | 需要定时器吗 |
|---|---|---|
| ~~PK 战帖被应战~~ | 对方提交成绩时 | ❌ 已实现 |
| 错题到期提醒 | 次日 19:00 | ✅ 每天扫库 |
| 连续学习断档预警 | 当天 21:00 仍未学习 | ✅ 每天扫库 |
| 赛季结算 / 奖励可领 | 赛季末 | ✅ 一天一次 |

**为什么只做 PK 场景**：它挂在「好友提交成绩」这个事件上，零定时器、零常驻成本。
而断档预警 / 到期提醒必须定时扫库 —— 云托管没有内置 cron，只能 Dockerfile 装 cron 且
**最小实例数 ≥ 1**（缩到 0 容器回收，cron 一起停），会产生常驻费用。

> **2026-10-28 决定：凡是要常驻容器的，一律不做。** 上面 3 个定时型场景就此封存，
> 不是待办、不是遗漏，是明确放弃。下面的「替代路径」只是留个路标，不是计划。

**如果以后真要重开，两条不用常驻的路**（都要额外基建，现在不值）：

1. **云函数定时触发器**：腾讯云开发的定时触发器按次计费、天然不占常驻容器。代价是本项目
   目前只有云托管、没有云函数，等于为两条提醒新引一套部署单元，还要处理两边的库连接。
2. **把「定时提醒」改成「进来自查」**：用户打开小程序时端上算「昨天断了 / 今天还没学」，
   就地弹一句，再挂个订阅按钮给他后一天的提醒。零常驻，但**只能在用户已经来了的时候提示**，
   对「本来就要流失的人」无效 —— 而这类人恰恰是提醒想捞的那批。

结论：这两条都不比常驻便宜到可以现在做。封存。

### 4.2 没有每日目标（P1，量级：小）

首页只有「今日已答 N 题」这个**结果**，没有目标值、没有完成反馈。

**建议**：让用户选 10 / 20 / 30 题，进度环 + 完成时的结算彩蛋。成本很低，但对「今天还差多少」的心理钩子很有效。

### 4.3 新手引导只覆盖 1/22（P1，量级：小~中）

> 修正：本文初稿写的是「全仓 0 处」，**这是错的**。复核后 `pkg-games/game/game.js:42-46` 有
> `TUTORIAL_STEPS`（3 步，讲补字母 / 连击 / Boss 反击），用 `ww_tutorial_done` 持久化，只走一次。
> 但 `grep -rln "tutorial"` 只命中 `game.js` 与 `game.wxml` —— 其余 21 款玩法一个都没有。

所以真正的问题是两头都不够：
- **广度**：新用户如果第一关恰好不是字母射击（主线第 1 关是射击，但玩法 Tab 可以直达别的），就没人教他；
- **深度**：现有 3 步只讲「怎么打这一局」，没讲「星星怎么变成段位」「为什么要复习」——而这两条才是留下来的理由。

**建议**：保留现有 3 步不动，另加一层「首次进 App」的 3 步（选年级 → 打一关 → 星星→段位），
以及把玩法操作引导抽成组件，让 21 个玩法都能挂（成本会落在「每个玩法写 1~3 句提示」上）。

### 4.4 没有补签（P2，量级：小）
