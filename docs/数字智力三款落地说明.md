## 一、认钟表（clock）

### 1.1 五档难度（只按关卡序号，不按年级）

| 关号 | 档位 | 内容 |
| --- | --- | --- |
| 1~6 | 认整点 | 整点 / 半点（分针只指 12 或 6） |
| 7~12 | 5 分刻度 | 分针走大格（5、10…55） |
| 13~18 | 1 分刻度 | 任意分钟，秒针不算 |
| 19~24 | 经过时间 | 分钟相加**不进位**（m + delta ≤ 59） |
| 25~30 | 跨小时 | 跨过整点 + 24 时制双向换算 |

### 1.2 表盘为什么不用 canvas / conic-gradient

- 原评估说"表盘要多写一块 UI"，复核意见估的是"纯 CSS 约 40 行"。实际做法：
  **60 个绝对定位的刻度 view**（每 5 个加粗）+ `transform-origin` 指到圆心旋转，
  指针是两根 `rotate()` 的圆角条。
- 特意**没用** `conic-gradient`：它在老基础库 / 部分安卓内核上不生效，会整块变成纯色圆，
  而刻度环是这个玩法的读题依据（1 分刻度档靠刻度数分钟），不能用"降级成没有"的写法。
- 时针角度 = `(h % 12) * 30 + m * 0.5`，**必须随分钟连续走**：半点时若时针还指着整点，
  孩子会照着表盘读出"3:00 或 4:00"，这是最伤的一类错。单测逐题断言这个公式。

### 1.3 关于"时间比较"

复核意见里 25~30 关写的是"跨小时 / 24 时制 / 时间比较"。实现时把**时间比较并进了选项干扰**，
没有单独成题：比较两个时刻本质就是"读两个表盘再比大小"，单独出一道纯文本的
"哪个最早"反而是这个玩法里最弱的一类题（没有表盘、没有读数训练）。
同一道 h24/h12 题的四个选项本身就是四个时刻，选错就是比较错。

### 1.4 题型与干扰项

- `read`：表盘 → 选时刻。干扰项取"分针当小时"「时针看错一格」「分钟读错一档」。
- `elapsed`：给起始时刻 + "再过 N 分钟"。干扰项取**忘了进位**（小时不动、分钟减 60）、
  「不该进位却进位」、分钟 ±5。
- `h24`：下午 → 24 时制（+12，12 点特殊）。
- `h12`：24 时制 → 下午几点（表盘会剧透答案，所以这一档**不画表盘**，改显大号数字牌）。

## 二、算术迷宫（maze）

### 2.1 复核意见的两条硬要求，怎么落地的

**① 必须有岔路（§2.3）。**
DFS 回溯生成的是完美迷宫，任意两格路径唯一 —— 玩家没有选择，等于"沿唯一路线连答口算题"。
做法：生成后 **braid**（把除宝箱外的死胡同全部再砸开一堵墙形成回路），并在死胡同里放宝箱。

第一版 braid 写成"45% 概率拆"，实测关 1 / 20 / 30 的回路数都是 **0** —— 因为死胡同本来就只有 5~7 个，
其中 2 个还是宝箱、2 个是起点终点。改成"全拆"之后：

```
关1  回路 1   关10 回路 2   关20 回路 1   关30 回路 4
```

单测断言：**每局 ≥ 1 个回路**、**除宝箱/起点/终点外没有死胡同**、**宝箱必须真在死胡同里**。

**② 星级按正确率（§1.3）。**
分母是**本关门数**，不是"答过的题数"。这一条很关键：迷宫能绕路，
如果分母取"答过几题"，绕开所有门直接走出口 → 正确率 100% → 3 星。
固定分母后，绕路只会少答 → 掉星，"速通"和"全清"形成真实权衡。

### 2.2 玩法参数

| 关号 | 档位 | 门数 | 题目 |
| --- | --- | --- | --- |
| 1~6 | 入门 | 3 | 20 以内加减 |
| 7~12 | 简单 | 4 | 100 以内加减 |
| 13~18 | 中等 | 5 | 表内乘除 |
| 19~24 | 进阶 | 6 | 两步混合（a×b±c） |
| 25~30 | 挑战 | 7 | 两位数乘法 / 带括号 |

- 机会 3 次（❤️×3），答错 -1，用完即结束（0 星）。
- 宝箱答对：机会 +1（上限 3），并把**答错的门重置成可重答**（"宝箱里是一块橡皮"）。
  这是支路的真实收益 —— 只是回血的话，满血时开宝箱毫无意义。
- 撤销没有做，改判"撞墙不扣机会"：6×6 的格子 54px，误触很常见，扣血代价太大。

### 2.3 UI 为什么是"格子 + 浮层"两套

6×6 时每格约 54px，`12 + 7` 塞不进格子。所以：
格子上只显示 🚪 / ✅ / ❌ / 🎁 / ✨ / 🏁 / 🚩 / 玩家形象，
**进格才弹浮层算式**（600rpx 卡片，2×2 选项）。这也是复核意见里点出的成本项。

## 三、汉诺塔（hanoi）

- **只做 3 柱**：`2ⁿ−1` 只在 3 柱成立；4 柱（Reve's puzzle）没有闭式解，
  原文"3 柱/4 柱两种变体 + 闭式解单测"自相矛盾。真要做 4 柱得 BFS 预计算。
- **只做 6 关**（3/4/5/6/7/8 盘）：最优解唯一，学会递归后每关同一套动作。
  8 盘 255 步是"小品"的长度上限。
- 最少步数不只写在常量里：单测用标准递归解生成 `2ⁿ−1` 步，**逐步调 move() 走完**，
  并穷举证明"少一步到不了"（3 盘 6 步内无解）。
- 星级照华容道 `starsFor`：1.15 倍内 3★ / 1.5 倍内 2★ / 其余 1★。
- 交互：点柱子拿起顶部盘 → 再点另一根放下；顶部盘会抬起 18rpx 并高亮柱子。
  提供「撤销」（回退状态与步数）和「重开」。

## 五、布局验收（用户要求：不能遮挡、不能有元素跳出界面）

微信开发者工具的自动化端口这两轮一直起不来（`shot-pages` 卡在启动），
所以沿用找规律那套办法：`demo/puzzle3-preview.html`，1rpx = 屏宽/750，
HTML 结构与 wxss 一一对应，用无头 Chrome 截图 + **页内几何自检**。

9 个场景：时钟第 1 关（375）/ 第 30 关数字牌（375）/ 第 28 关 24 时制（390）；
迷宫第 1 关（375）/ 第 30 关 7 门（375）/ 答题浮层（375）；
汉诺塔 3 盘 / 8 盘 / 结算弹层。

自检项：关键行越界、关键行相互遮挡、表盘越出题板、**迷宫逐格越出棋盘**、
汉诺塔盘子越出轨道、点击区 < 44px、弹层卡片出屏。

### 截图抓到的三个真问题（都已修）

1. **迷宫格子被压扁**。`.board` 只给了 `grid-template-columns`，没有行高，
   6 行的高度全由 emoji 撑 → 格子是 54×30 的扁块。
   修：`grid-auto-rows: {{cellW}}rpx`。
2. **汉诺塔柱子只占卡片下半截**。`.peg` 写死 400rpx，而 `.tower` 是 `flex:1`，
   大屏上题板被撑高后柱子下面只剩一条。修：`.peg { height: 100% }`、
   `.rod { height: calc(100% - 40rpx) }`（8 盘堆高 323rpx，留 40rpx 余量）。
   顺带把柱子编号从 `bottom:-6rpx` 挪到顶部 —— 原来被题板 padding 裁掉一半。
3. **预览页自己的 box-sizing 与 wxss 不一致**。预览页全局 `* { box-sizing: border-box }`
   把棋盘改成了 border-box，而 wxss 里 `.board` 是 content-box →
   预览页格子比棋盘宽 8px（自检抓到的"格子溢出棋盘 右 4.0px"）。
   这是预览页的 bug，不是小程序的；修预览页并保留这条检查，防止以后改样式时再飘。

修完后 **9/9 场景：无越界 / 无遮挡 / 点击区合格**。
