# 首页入口兼容规划（UI 重做一期 · 战士主题版）

> 背景：首页从「一堆入口的大厅」改成「养成你的战士」——战士立绘 / 皮肤收集条 / Boss 预告
> 占掉了大半首屏。**风险不在视觉，在入口**：重排时漏一个按钮，页面不会报错，只是玩家少一条路。
> 本文是重做前 12 个入口的**逐条映射**，以及「入口分层」规则，配合守卫测试
> `tests/unit/index-entries.test.js`（删入口即红）使用。

## 一、分层规则（先定这个，再谈放哪）

| 层 | 放什么 | 落位 | 判断标准 |
|---|---|---|---|
| L1 主题区 | 战士立绘、皮肤收集条、Boss 预告、出战 | 首屏顶部 | 决定「我为什么回来玩」——不是入口，是动机 |
| L2 主操作 | 出战（继续挑战） | 主题区下方，全屏唯一橙色 | 一屏之内必然可见 |
| L3 高频入口 | 每日一题、排行榜、每日挑战、赛季、好友 PK、今日目标 | 出战之后，2~3 行内 | 每天/每周会用，值得占首页 |
| L4 长尾功能 | 成就、错题本、学习报告、自定义关卡、教材、签到、管理 | **不放首页**，走 tab（学习 / 我的） | 低频、有明确归属页，放首页只会稀释主题 |

**兼容红线**：L1~L3 的入口一个都不能少；L4 的入口必须能从 tab 一步到达（本文第四节已核对）。

## 三、首屏可见性预算（750rpx 宽基准）

| 模块 | 高度（约） | 累计 |
|---|---|---|
| HUD 胶囊条 | 76rpx | 76 |
| 战士舞台（立绘 316rpx） | 330rpx | 406 |
| 等级进度卡 | 96rpx | 502 |
| 皮肤收集条 | 190rpx | 692 |
| Boss 预告卡 | 140rpx | 832 |
| 出战按钮 | 130rpx | 962 |

iPhone 8 级别的可视区约 1230rpx（已扣 tabBar）：**首屏能看到出战按钮 + 今日目标**，
小屏（iPhone SE ≈ 1100rpx）也能完整看到 Boss 卡与出战按钮的下半部分。
若后续觉得首屏太挤，优先压缩顺序：皮肤收集条（改 4 格）→ 战士舞台（立绘降到 280rpx），
**不要靠删入口解决**。

## 四、不放首页的功能 & 它们在哪（已核对，无孤儿页）

| 功能 | 页面 | 入口所在 |
|---|---|---|
| 成就 | `pages/achievement` | 我的 tab |
| 错题本 / 复习 | `pages/wrong-book` / `wrong-review` | 我的 tab、学习 tab、学习报告页 |
| 学习报告 | `pages/report` | 学习 tab |
| 教材版本 / 题库 / 签到 | `pages/bank` / `checkin` | 学习 tab |
| 自定义关卡 / 编辑器 / 分享 | `pages/custom-levels` 等 | 学习 tab、关卡编辑页 |
| 皮肤图鉴 | `pages/avatar` | **首页（新增）+ 我的 tab** |
| 段位详情 / 段位考 | `pages/rank-info` / `rank-exam` | 首页 HUD、我的 tab |
| 管理后台 | `pages/admin` | 我的 tab（仅管理员可见） |

核对方式：静态扫描 `miniprogram/**` 内所有 `/pages/xxx/xxx` 引用，44 个注册页面均有非自身来源
的引用，**没有孤儿页**。

## 五、守卫 & 回归

- `node tests/unit/index-entries.test.js` —— 入口清单 + 方法定义 + 跳转目标 + 主题区四件套
  （已登记进 `e2e/lib/modules.js` 的 `pages` 模块，`--module=pages` 会跑到）。
- `node e2e/check-taps.js` —— 所有 bindtap/catchtap 必须指向已存在的方法。
- `node e2e/check-wxss.js` —— 按钮高度写了就要写 line-height（首页 HUD 圆按钮踩过）。
- 后续批次改 4 个 tab 页时，**先跑这三条**再截屏复查。
