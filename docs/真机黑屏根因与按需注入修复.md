# 真机黑屏根因与按需注入修复（2026-09-12 深夜）

> 结论先说：真机「排行榜、错题本点进去黑的 / 进不去」不是网络问题、不是云托管问题，
> 而是 **① 7 个页面缺 `page.json`** 与 **② 之前把「按需注入」当元凶删掉** 两件事叠加出来的。
> 现在按需注入**已按微信要求开启**，缺的 `page.json` 已补齐，并加了 3 道回归闸门。

## 一、真机现象（用户日志，22:12 / 22:38 两次）

```
- path: pages/rank/rank  (openType: navigateTo)
SystemError (jsEnginScriptError)
Component is not found in path "wx://not-found".
  recurseComponentImpl@https://lib/WASubContext.js
Page "pages/rank/rank" has not been registered yet.
```

后来（`app.json` 里删掉 `lazyCodeLoading` 之后）升级成整页崩：

```
SystemError (jsEnginScriptError)
Can't find variable: __wxAppCode__
  recurseUsingComponents@https://lib/WASubContext.js
  injectComponentsRecursively@https://lib/WASubContext.js
routeDone with a webviewId 110 is not found
```

清缓存、删小程序、重装开发者工具都不管用 —— 因为问题在**代码包本身**，不在缓存。

## 二、证据链（都是机器上可复核的硬证据）

1. **报错页面 = 缺 `page.json` 的页面**
   22:12 的日志里，报错的只有 `pages/rank/rank` 与 `pages/wrong-book/wrong-book`；
   同一份日志里 `pages/index/index`、`pages/study/study`、`pages/daily-question/daily-question`
   （这三页都有 `page.json`）完全正常。仓库里当时缺 `page.json` 的正好是 7 页：
   `rank / wrong-book / wrong-review / achievement / avatar / checkin / level-share`。

2. **`__wxAppCode__` 是 wcc 编译产物里的全局映射，按需注入下框架靠它找页面/组件**
   在开发者工具安装目录里搜到的框架源码（真机调试 toolkit `WAWebview.js`）：

   ```js
   recurseUsingComponents(e){
     if(!kr())return e;              // kr = () => __wxConfig.isLazyLoad
     var t=__wxAppCode__, ...        // 无 typeof 保护，取不到就直接 ReferenceError
   }
   injectComponentsRecursively(e,t,i,n){
     if(kr()){ ... } else t()
   }
   ```

   也就是说：**运行时说「我要按需注入」，但编译产物里没有 `__wxAppCode__`** → 报错。

3. **真机调试的运行时会强制走按需注入**
   toolkit 的特性开关里写着 `lazyCodeLoadingForDevTool: true`，并且
   `checkSupportLazyLoading()` 就读这个开关。这解释了为什么「手机上报错、开发者工具里正常」。

4. **本地编译确实跟着 `app.json` 变**
   工具日志：`app.json` 没这一项时是 `isLazyLoad: false`；加回 `lazyCodeLoading` 后编译缓存键变成
   `isLazyLoad:true`。（工具对 `isLazyLoad` 的判定源码：
   `C.isLazyLoad = 支持按需注入 && app.json.lazyCodeLoading === 'requiredComponents'`。）

5. **微信官方要求/推荐开启**
   [按需注入和用时注入](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/lazyload.html)：
   基础库 2.11.1 起支持，开启后「仅注入当前访问页面所需的页面与自定义组件」；
   同时明确「页面 JSON 中定义的所有组件、app.json 中 `usingComponents` 的全局组件都会被视为
   页面的依赖并进行注入」。

## 三、根因

1. **7 个页面缺 `page.json`。** 按需注入下，框架是按
   `__wxAppCode__["<页面路径>.json"]` 来找页面的 `usingComponents` 依赖的；缺 json 的页面
   查不到依赖，就被解析成 `wx://not-found` 占位 —— 表现就是**点进去黑屏 / 进不去**
   （真机调试时尤其明显）。
2. **把「按需注入」当成黑屏元凶删掉，反而把「部分页面点不进去」升级成「整页崩」。**
   删掉 `lazyCodeLoading` 后编译产物里不再生成 `__wxAppCode__`，而真机调试的运行时仍强制按需
   注入，于是直接 `Can't find variable: __wxAppCode__`、路由失败。
   （当时另一个真实问题是 `app.wxss` 的深色媒体查询，已单独修掉，见提交 `1537d3c`。）

## 四、本次修复

| 改动 | 文件 | 说明 |
| --- | --- | --- |
| 补 `page.json` | `miniprogram/pages/{rank,wrong-book,wrong-review,achievement,avatar,checkin,level-share}/*.json` | 内容 `{"usingComponents": {}}`，无自定义组件、不改变页面表现 |
| 开启按需注入 | `miniprogram/app.json` | `"lazyCodeLoading": "requiredComponents"` |
| 结构护栏 | `e2e/structure-check.js` | 页面必须「四件套」齐全（新增 json）+ `lazyCodeLoading` 必须开启 |
| 规则反转 | `e2e/check-wxss.js` | 由「禁止 lazyCodeLoading」改为「**必须**开启」，并写清历史误判原因 |
| 新增探针 | `e2e/probe-pages-load.js` | 逐页监听 console/exception，命中 `__wxAppCode__` / `wx://not-found` / `has not been registered` 即 FAIL；已挂进 `e2e/run-all.js`（阶段 `load`） |

## 五、验证

```bash
node e2e/run-all.js --no-e2e          # 静态 + 单测（结构护栏含「四件套齐全」）
node e2e/probe-pages-load.js          # 35 页逐页加载：0 命中
node e2e/run-all.js                   # 全量 16 阶段
```

本地结果：按需注入开启后，35 个页面逐页加载 **0 命中**；全量 16 阶段 PASS。

## 六、真机复验步骤（需要人工做一次）

1. 开发者工具里 **重新编译**（改过 `app.json`，建议「工具 → 编译」或重开项目）。
2. 上传新版本（版本号 +1）。
3. 手机上：删掉旧的小程序入口 → 重新扫码进开发版/体验版。
4. 重点点：**排行榜 → 错题本 → 成就 → 每日一题 → 继续挑战 → 24 点 → 连连看 → 贪吃蛇**。
5. 如果还有报错，把手机上的完整日志发我：只要 `Can't find variable: __wxAppCode__` 不再出现，
   剩下的就是业务层问题，另查。

## 七、遗留

- 真机调试（尤其是 iOS）对 `app.json` 的改动比较敏感，改动后没重开项目会读到旧配置 ——
  以后凡是动 `app.json`，先重开项目再真机验证。
- `art/`（成就图标、段位徽章）走云托管 URL，不进包；真机上如果显示 emoji 占位，说明该图没取到。
