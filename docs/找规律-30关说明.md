# 找规律 · 30 关说明（2026-10-18 新增）

> 数字智力第 9 款。本篇记录：玩法口径、题型档位表、星级与星星上限、干扰项策略、
> 接入清单，以及**布局验收**（三种屏宽的实测结论与踩过的坑）。

## 一、定位

| 项 | 内容 |
| --- | --- |
| 板块 | 数字智力（`section: 'casual'`），不做题库 |
| 入口 | 玩法页 → 自由玩 → 找规律 → 关卡页 → 进入 |
| 关卡 | **30 关**，每关 **10 题** |
| 玩法 | 给一串数（或一串符号），问号处该填什么；4 选 1 |
| 教学增量 | **答完立刻公布规则**（「每次 +3」「平方数：2²、3²…」），这是它相对其他玩法唯一不可替代的地方 |
| 难度口径 | **只看关卡序号，不接年级** |

### 为什么不接年级

用户 2026-10-18 拍板：数字智力和年级关系不大。三条实证：

1. **与现有实现一致**：`sudoku / math24 / klotski / onestroke / memory-grid / tw2048 / g2048` 的引擎里 `grade` 零引用；只有 `math-sprint / balance` 按 `gradeScale` 出题 —— 那是学科口算（一关一个年级），和益智不是一类。
2. **存档与榜单已经是"无年级"**：星星 key 是 `pattern_7`，上报是 `grade: 'all'`。若同一关按年级出不同题，同一个 `level` 对应不同难度，进度榜与星级都不可比。
3. **关卡号本身就是闸门**：第 1 关永远不含斐波那契，能到第 25 关的人已经过了 24 道门槛。这比"系统按年级分配"更贴合实际能力。

源码级护栏：`pattern.test.js` 断言引擎里不得出现 `grade / getLastGrade / gradeScale`。

## 二、题型与档位

题型族**逐档累加**（只增不减），高关偶尔还会出简单题当送分题。

| 关号 | 档位 | 允许题型 | 说明 |
| --- | --- | --- | --- |
| 1~6 | 入门 | 图形规律、等差(+1~+5) | 第 1 关就是图形题，入门不需要读数 |
| 7~12 | 简单 | + 递减、交替(+a,+b) | |
| 13~18 | 中等 | + ×2 等比、平方数 | |
| 19~24 | 进阶 | + 二阶等差 | |
| 25~30 | 挑战 | + 斐波那契式 | 全部放开，混合出题 |

实现：`miniprogram/game/pattern.js` 的 `TIERS[].weights`。权重既决定"这档允许哪些题型"，也决定抽取概率。

### 题面规格

- 数字题固定 **6 格**（5 已知 + 1 问号），图形题固定 **8 格**（7 已知 + 1 问号）。
  **格数固定是为了布局稳定** —— 珠子不会因为题目不同忽宽忽窄。
- 数值上限：不超过 3 位数（等比起点 2~4，最大 128；平方数最大 81；斐波那契最大 50）。
- 同关 10 题**题面不重复**（`genLevel` 撞了就换种子重抽，最多重试 20 次）。

## 三、星级与星星上限

- 星级统一按正确率：`challenge.starsByRightRate(right, 10)`，阈值 90 / 70 / 60 → 9 题 3 星、7 题 2 星、6 题 1 星。
- **0 星不算过关**（关卡页据此解锁下一关），但照样上报成绩。
- **星星上限 30 × 3 = 90**。这是硬约束：`saveStars` 的星会被首页 `getAllStars()` 汇总进段位/皮肤门槛，"无限关卡 = 无限刷星"。所以关卡表有限，只有**关内换题**（重玩换 seed）。

## 四、干扰项策略

复核意见里定的原则："像但不对"。

1. **错规则回算**：把等差当等比、把平方数当等差、斐波那契当 ×2、交替漏一步……
   例：`4 9 16 25 36 ?=49` → 干扰项 60（当等差）、36（上一个平方数）、64（下一个平方数）。
2. **邻近偏移**：±1 / ±2，只在前面的候选被过滤掉时补位。
3. **四项互异、恰有一个正确答案**；数字题干扰项必须是正整数。
4. **图形题**：优先放"序列里出现过的符号"（最强干扰，孩子容易数错位置），再补池子里的其他符号。

## 六、布局验收（重点：不能遮挡、不能跳出界面）

微信开发者工具自动化端口本轮仍然起不来（`shot-pages` 卡在启动，近 3 分钟无输出后手动停掉），
改用 **`demo/pattern-preview.html`** 做 1:1 布局验收：同一套 rpx 尺寸（`rpx × 屏宽/750`），
在无头 Chrome 里渲染四个场景，并在页面内跑自动几何检查。

### 覆盖场景

| 场景 | 屏 | 内容 |
| --- | --- | --- |
| 1 | 375×667（可视 603px） | 第 1 关数字题，6 格，考前 |
| 2 | 375×667 | 第 28 关图形题，8 格（最挤），答对态 |
| 3 | 390×844（可视 753px） | 第 13 关，答错态（正确答案 + 规则解释） |
| 4 | 430×932（可视 841px） | 第 30 关斐波那契，两位数 |
| 5 | 375×667 | **结算弹层**（2 星，含「再完成 1 题就是 3 星」提示） |

自检项：横向越界、纵向超出屏幕、脚注与选项重叠、珠子压到题板边缘、选项点击区 <44px、
**结算卡四边是否都在屏幕内**（任一边出去 = 按钮点不到）。

**结论：五个场景全部无越界 / 无遮挡 / 无重叠。** 375 屏内容高 603px（正好铺满），
430 屏 841px（铺满），底部均无溢出；结算卡 600rpx 宽，在 375 屏上左右各留 37px，上下余量充足。

### 截图发现并修掉的三个问题

1. **珠子压到题板边缘**。`cellW` 第一版按 686rpx（页面可用宽）算，但珠子是在**白色题板内**
   （题板左右还有 20rpx padding）→ 6 格总宽正好等于题板内宽，左右贴边、8 格时溢出。
   修：基准改 `646rpx`。**教训：只量容器 rect 发现不了子元素溢出，要逐格量。**
2. **深色 emoji 压在绿底上看不见**。答对态原来是实心绿块 + 白字，图形题的选项是 emoji，
   🟤 这类深色 emoji 放在绿底上几乎不可见。修：对错态改成「浅底 + 4rpx 粗描边」。
3. **珠子在白题板上"消失"**。白底白块只靠阴影区分，几乎看不出来。修：珠子改浅紫底 + 细描边。

另外两处视觉调整：图形题选项字号 60rpx（emoji 比数字显小）、珠子字号按格宽 0.42 倍。

### 顺带修掉的一个文案 bug

结算标题原本写 `title="{{showNext ? '过关！' : '全部通关！'}}"`，但 `settle-pop` 的逻辑是
`title || (win ? '通关成功！' : '再接再厉！')` —— **0 星失败时也会显示「全部通关！」**（配红色标题）。
改成由页面算 `overTitle`：失败传空串，成功才给「过关！/ 全部通关！」。
