# 管理员后台与隐私口径（2026-09-13）

## 一、能力

小程序内隐藏入口：**「我的」页 → 连点版本号 5 次** → 输入管理口令 → 管理后台。包含：

- **运营概览**：注册人数、在线人数（最近 5 分钟有成绩上报）、今日活跃、今日新增、累计答题、段位分布。
- **用户列表**：昵称、**微信名**、掩码 openid、注册时间、最近活跃、段位、答题局数；支持按昵称搜索、分页。

## 二、隐私口径（用户 2026-09-13 明确）

| 字段 | 谁能看 | 说明 |
| --- | --- | --- |
| `nickname`（展示昵称） | 所有人 | 排行榜就是它，用户自设，照旧展示 |
| `wx_nickname`（微信名） | **仅管理员** | 单独字段，公开接口一律不返回 |
| `openid` | 仅管理员（且打码） | 管理端返回前 6 后 4 |

> 微信平台限制（重要）：2022 年起微信收回了静默获取昵称头像的接口，`getUserInfo` / `getUserProfile`
> 只返回匿名「微信用户」加默认头像。唯一合规来源是**「头像昵称填写能力」**（昵称页的
> `<input type="nickname">`，微信昵称会作为默认值带出来，用户点一下确认）。
> 所以「注册时就能拿到微信名」等于**注册流程里让用户确认一次昵称**；我们本来就是这么走的
> （未设昵称进昵称页），现在那一刻会同时把微信名写进 `users.wx_nickname`。
> 如果用户始终没确认过昵称，管理端会显示「（未获取）」，这是平台限制，不是漏做。

## 三、上线前需要你做两件事

> 进度（2026-09-13 夜）：**第 2 条 SQL 你已执行**，线上用测试账号探针验证通过
> （写入 `wx_nickname` 后 `/api/admin/check` 回读一致）。剩下只有第 1 条：云托管环境变量
> 把 `ADMIN_OPENIDS` 配上你的 openid（`ADMIN_WX_NICKNAMES` 同时存在也可以，但建议择一）。

### 1. 云托管环境变量（不配则**没有管理员**，这是有意的安全默认）

在云托管控制台 → 服务 `express-g0hk` → 环境变量，按用户 2026-09-13 的要求配置：

```
ADMIN_WX_NICKNAMES=h842917647      # 管理员微信名白名单（只有这个微信名是管理员）
ADMIN_PASSCODE=<可选，管理口令>     # 管理页还可以额外要求输入口令
ADMIN_OPENIDS=<可选，openid 白名单> # 最稳；上线后建议加到这一条
```

三者满足其一即为管理员；都没配则谁都不是管理员（默认安全）。

⚠️ **微信名白名单的风险**（配之前请知道）：微信名用户可以自己改、也可能重名 ——
谁把昵称改成 `h842917647` 就能进管理端。它适合开发/测试期的便捷方式；上线后建议改用
`ADMIN_OPENIDS`（管理页会显示当前账号的 openid 掩码，云托管日志里也能看到完整 openid）。

> 2026-09-13 加固：`wx_nickname` 列就绪后，白名单**只认 `wx_nickname`**，
> 不再回落到「展示昵称」——否则谁把展示昵称改成 `h842917647` 就能越权进管理端。
> 列未就绪（DDL 没执行）时仍按旧行为用展示昵称兜底，保证管理端可用。

### 2. 一条 SQL（生产库加列，只影响微信名存储）

```sql
ALTER TABLE users
  ADD COLUMN wx_nickname VARCHAR(64) NULL COMMENT '微信昵称（仅管理员可见）';
```

> 没执行也不影响小程序运行：服务端写入微信名失败会被兜住（只存昵称/头像，日志提示），
> 管理端该字段显示「（未获取）」。

## 四、接口与护栏

| 接口 | 说明 |
| --- | --- |
| `GET /api/admin/check?passcode=` | 校验是否管理员（管理页「进入」先调它） |
| `GET /api/admin/stats?passcode=` | 运营概览 |
| `GET /api/admin/users?passcode=&page=&pageSize=&q=` | 用户列表（含微信名） |

- 权限实现：`server/admin-auth.js`（`ADMIN_OPENIDS` 白名单 / `ADMIN_PASSCODE` 口令；纯函数，单测覆盖默认拒绝、白名单、口令、昵称脱敏、openid 掩码）。
- 未通过校验统一返回 `4003 需要管理员权限`。
- 入口隐藏加服务端二次校验：即使有人猜到 `/pages/admin/admin`，没有口令也拿不到任何数据。

## 五、⚠️ 微信名采不到的真凶：隐私接口未声明（2026-09-19）

**现象（用户遇到的报错）**：

```
[Component] <input>: showNicknameAccessory:fail
  api scope is not declared in the privacy agreement, errno:112
```

**官方文档原文**（[隐私协议开发指南 · 五、常见错误说明](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)）：

> `{ "errMsg": "A:fail api scope is not declared in the privacy agreement", "errno": 112 }`
> 使用到了 A 隐私接口，但是开发者**未在「MP后台-设置-服务内容声明-用户隐私保护指引」中声明收集 A 接口对应的隐私类型**。
> 补充的隐私类型声明，**将在 5 分钟后生效**。

**这意味着什么**：`<input type="nickname">`（昵称填写能力）被平台拦下了 ——
用户点不出「使用微信昵称」，所以**微信名永远采不到**。
这正是「管理员看不到用户微信名」的根因，**不是代码问题**。
（因此之前采到的那条 `追梦001222` 是用户手输的，不是微信昵称。）

**需要你做的（只有账号持有人能做，我无法代做）**：

1. 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 「设置」→「服务内容声明」→「用户隐私保护指引」→ 修改；
2. 勾选与**微信昵称、头像**相关的收集项（平台里的项名可能是「微信昵称」「头像」或「用户信息」）；
3. 保存提交 —— 官方说明**补充声明 5 分钟后生效**，不用等常规审核周期。

**代码侧不需要改**：

- 官方说明 2023-10-17 之后「**不论 app.json 中有没有配置 `__usePrivacyCheck__`，隐私相关功能都会启用**」，
  且官方隐私授权弹窗会**自动展示、无需开发者适配**，所以我们不加 `__usePrivacyCheck__`、也不自己写
  `onNeedPrivacyAuthorization`。
- 页面里自研的「登录前先同意《用户协议与隐私政策》」弹窗是**产品自己的流程**（`utils/auth.js` 的
  `ensureAgreement`），与微信官方隐私弹窗并行、互不冲突。
- 采集失败时有降级：昵称面板点不出来也能**手输昵称**，注册流程不会卡住。

**声明生效后要复验**：进「编辑资料」→ 点昵称框 → 应能弹出「使用微信昵称」→ 点一下 →
保存 → 管理端该用户应显示出微信名。

### 同源问题：头像也换不了

`<button open-type="chooseAvatar">` 与昵称填写**同属隐私接口**，所以上面「服务内容声明」里
也要把**头像**勾上，否则点「点击更换头像」不会弹选择面板。

另外头像还有一个**独立的坑**（与隐私无关，已修）：
`chooseAvatar` 返回的是**微信临时文件路径**（`wxfile://tmp_xxx`），
以前直接存进 `users.avatar_url` —— 结果本人重启小程序后失效、**别人手机上必然裂图**。
现在改成：前端压到 160px → 上传到我们自己的服务 → 存库 → `avatar_url` 写**稳定地址**。

## 六、头像建表 SQL（2026-09-19 新增，需要执行）

```sql
CREATE TABLE IF NOT EXISTS `avatar_blobs` (
  `openid`    VARCHAR(64)  NOT NULL COMMENT '所属用户 openid（一人一张，覆盖写）',
  `mime`      VARCHAR(32)  NOT NULL DEFAULT 'image/png' COMMENT '图片 MIME',
  `data`      LONGBLOB     NOT NULL COMMENT '图片二进制',
  `version`   BIGINT       NOT NULL DEFAULT 0 COMMENT '内容版本号（破缓存用）',
  `createdAt` DATETIME     NOT NULL,
  `updatedAt` DATETIME     NOT NULL,
  PRIMARY KEY (`openid`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户头像图';
```

不执行也能跑：上传接口会报错、读取接口返回 404，头像回落到默认展示，不影响其它功能。

## 七、头像相关接口

| 接口 | 说明 |
| --- | --- |
| `POST /api/user/avatar` | 上传头像（body: `{mime, data(base64)}`，≤512KB），返回稳定 URL 并写回 `users.avatar_url` |
| `GET /api/avatar/:openid` | 读头像图片（**公开可读**：排行榜等公开展示要用，`<image>` 也不带自定义头） |
