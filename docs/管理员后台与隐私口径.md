# 管理员后台与隐私口径（2026-09-13）

## 一、能力

小程序内隐藏入口：**「我的」页 → 连点版本号 5 次** → 输入管理口令 → 管理后台。包含：

- **运营概览**：注册人数、在线人数（最近 5 分钟有成绩上报）、今日活跃、今日新增、累计答题、段位分布。
- **用户列表**：昵称、**微信名**、掩码 openid、注册时间、最近活跃、段位、答题局数；支持按昵称搜索、分页。

## 二、隐私口径（用户 2026-09-13 明确）

| 字段 | 谁能看 | 说明 |
| --- | --- | --- |
| `nickname`（展示昵称） | 所有人 | 排行榜就是它，用户自设，照旧展示 |
| `wx_nickname`（微信名） | **仅管理员** | 单独字段，公开接口一律不返回 |
| `openid` | 仅管理员（且打码） | 管理端返回前 6 后 4 |

> 微信平台限制（重要）：2022 年起微信收回了静默获取昵称头像的接口，`getUserInfo` / `getUserProfile`
> 只返回匿名「微信用户」加默认头像。唯一合规来源是**「头像昵称填写能力」**（昵称页的
> `<input type="nickname">`，微信昵称会作为默认值带出来，用户点一下确认）。
> 所以「注册时就能拿到微信名」等于**注册流程里让用户确认一次昵称**；我们本来就是这么走的
> （未设昵称进昵称页），现在那一刻会同时把微信名写进 `users.wx_nickname`。
> 如果用户始终没确认过昵称，管理端会显示「（未获取）」，这是平台限制，不是漏做。

## 三、上线前需要你做两件事

### 1. 云托管环境变量（不配则**没有管理员**，这是有意的安全默认）

在云托管控制台 → 服务 `express-g0hk` → 环境变量，按用户 2026-09-13 的要求配置：

```
ADMIN_WX_NICKNAMES=h842917647      # 管理员微信名白名单（只有这个微信名是管理员）
ADMIN_PASSCODE=<可选，管理口令>     # 管理页还可以额外要求输入口令
ADMIN_OPENIDS=<可选，openid 白名单> # 最稳；上线后建议加到这一条
```

三者满足其一即为管理员；都没配则谁都不是管理员（默认安全）。

⚠️ **微信名白名单的风险**（配之前请知道）：微信名用户可以自己改、也可能重名 ——
谁把昵称改成 `h842917647` 就能进管理端。它适合开发/测试期的便捷方式；上线后建议改用
`ADMIN_OPENIDS`（管理页会显示当前账号的 openid 掩码，云托管日志里也能看到完整 openid）。

### 2. 一条 SQL（生产库加列，只影响微信名存储）

```sql
ALTER TABLE users
  ADD COLUMN wx_nickname VARCHAR(64) NULL COMMENT '微信昵称（仅管理员可见）';
```

> 没执行也不影响小程序运行：服务端写入微信名失败会被兜住（只存昵称/头像，日志提示），
> 管理端该字段显示「（未获取）」。

## 四、接口与护栏

| 接口 | 说明 |
| --- | --- |
| `GET /api/admin/check?passcode=` | 校验是否管理员（管理页「进入」先调它） |
| `GET /api/admin/stats?passcode=` | 运营概览 |
| `GET /api/admin/users?passcode=&page=&pageSize=&q=` | 用户列表（含微信名） |

- 权限实现：`server/admin-auth.js`（`ADMIN_OPENIDS` 白名单 / `ADMIN_PASSCODE` 口令；纯函数，单测覆盖默认拒绝、白名单、口令、昵称脱敏、openid 掩码）。
- 未通过校验统一返回 `4003 需要管理员权限`。
- 入口隐藏加服务端二次校验：即使有人猜到 `/pages/admin/admin`，没有口令也拿不到任何数据。
