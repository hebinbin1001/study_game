## 0. 先回答两个问题

### 0.1 要不要做「深色 + 浅色」两套主题？

**结论：现在不做。** 不是做不了，是现在做代价最高、收益最低。

三条理由，按分量排序：

**① 成本取决于令牌化，而现在是最贵的时候。**
深色主题的本质是"第二套变量值"——前提是所有颜色都走 token。实测 `var(--*)` 全站只用了 **50 次**（基本都在 `app.wxss` 自己定义变量的地方），硬编码色值 **2115 次 / 580 种**。
现在做深色 = 给 580 个色值各配一个深色值，且必然漏。令牌化完成后做 = 只写 24 个值。
**同一件事，成本差 20 倍。**

**② 卡通硬阴影风格与深色底天然冲突。**
本项目的手感靠 `box-shadow: 0 8rpx 0 rgba(0,0,0,.10)` 这种"底部硬阴影"撑起塑料片质感。深色底上黑色硬阴影会变成一圈"脏边"，必须整套改成发光或描边——这不是换色，是换材质体系。

**③ 已经踩过一次，且写进了项目硬约定。**
`app.wxss:740` 保留了完整事故记录：只改 `page` 背景的 `prefers-color-scheme: dark`，让 18 个"没自带背景色"的页面在深色手机上**整片发黑**，开发者工具默认浅色复现不出来。`AGENTS.md §5` 因此写明"禁止再出现半成品深色模式"。

**什么条件下可以做：**
令牌化（P0）完成 + 浅色全站统一之后。那时它只是"加一套变量覆盖 + 8 张 tab 深色图标（包内还有 178KB 余量）+ 51 页深色截图回归"，**3~4 天**，而不是现在的 3~4 周。建议作为独立小版本排在视觉重构之后。

> 顺带纠正一个容易混的概念：**"场景化深色" ≠ "系统深色模式"**。
> 对局页做成深色战场（Boss 立绘在暗底上更突出）是**单页配色决策**，不影响全局主题，也不受上面三条约束。这个建议保留，见 §4。

### 0.2 为什么这次不会重蹈 10-09 的覆辙？

上次的链路是「出整屏效果图 → 照着写 CSS」，失败原因文档 §1 已分析过三条。**但那条链路的问题还没被真正堵住**，证据是这 19 天的指标变化：

| 指标 | 10-09 实测 | 10-28 实测 | 变化 |
|---|---|---|---|
| 不同色值 | 330 | **580** | +76% |
| 色值出现次数 | 1613 | **2115** | +31% |
| 字号档位 | 38 | **45** | +7 档 |
| 页面数 | 44 | **49** | +5 |
| `var(--*)` 使用 | 0 | **50** | 仍≈0（都在定义处） |

**结论：没有护栏的规范 = 不存在的规范。** 上次文档写得很好，但一行都没落地，反而漂得更远。
所以本次的顺序必须是 **护栏 → 令牌 → 视觉 → 逐页**，而不是反过来。

## 1. 诊断：真正缺的不是"好看"

你说"没有好的想法"，我判断问题不在审美，在这三件事：

**① 缺视觉隐喻。** 现在 4 个核心页各说各话：首页是"天空 + 战士舞台"，关卡页是"白卡列表"，对局页是"白色战场卡片"，结算页是"天空 + 白面板"。它们共用一套配色，但**没有一个共同的空间概念**把它们串起来。玩家的感受就是"每一页都还行，连起来不像一个游戏"。

**② emoji 与插画混用，资产断层。** 首页 HUD 是 🏫⭐🔥，三宫格是 🏆🏅🤝，而战士和 Boss 是精细插画。`art/` 里其实已有 12 个玩法图标、8 个 UI 按钮、81 张段位徽章、56 张立绘——**资产不少，但没被用起来**，因为没人定"哪里用图标、哪里用 emoji"。

**③ 没有层级，只有并列。** 首页一屏 11 个块，全部是白卡、同样的圆角、同样的阴影、同样的权重。玩家不知道先看哪里。这是"说不清哪里不对"的直接来源。

## 2. 三个视觉方向（选一个，不要混）

### 方向 A · 天空塔（推荐）

**一句话**：整站是**一座通往天空的塔**，玩家从地面往上打。

| 页面 | 长什么样 |
|---|---|
| 首页 | 你在塔的第 N 层。立绘站在云台上，**上方**是下一层 Boss 的剪影，**下方**是云海与已通过的层。一屏只有「向上」一个方向暗示 |
| 关卡 | 塔的剖面：每 5 关一层，当前层展开成云阶（可见 5 个台阶），其他层折叠成楼层条（`第 3 层 · 已通`） |
| 对局 | 当前层的战斗场景。深色战场（复用 `--boss-bg1/bg2` 暗紫），Boss 立绘占屏 40% |
| 结算 | 击败 Boss → 整页向上"跃迁"一层，星级在云层上点亮 |
| 段位 | 塔的高度：青铜在地面，王者近云端；徽章沿用现有 81 张 |

**为什么推荐它：**
1. **与现有结构天然同构**——30 关、每 5 关一段、第 30 关 Boss，本来就是"层"的结构，不需要为了视觉改玩法。
2. **复用现有资产最多**——立绘、Boss、段位徽章全都能用上，**不需要新素材**（云层用 CSS 画）。
3. **一箭双雕**——它同时是信息架构方案：关卡页的四层筛选（学段/分类/进度/列表）在"塔"里自然收敛成一层。
4. **竖屏优势**——竖向纵深正是小程序竖屏最擅长的事，横排卡片反而是逆势。

**风险与解法：** 30 关一屏放不下 → 每层 5 关，一屏显示 2~3 层，当前层展开、其余折叠。可达性不降（折叠层一次点击展开）。

### 方向 B · 战斗手账

**一句话**：把成长做成一本贴纸手账。

白卡变"纸片"（微旋转 + 胶带固定），成就/皮肤/段位都是"贴上去的贴纸"，标题用手写体。
**成本最低**（几乎不用新素材），**差异化中等**。
**不推荐的理由**：手账风偏"软"、偏静态记录，与"战士打 Boss"的爽感方向相反；而且本项目核心是每日刷题，手账气质更像"日记 App"。

### 方向 C · 街机 HUD

**一句话**：强化打击感，UI 做成街机对战面板。

斜切面板、金属边框、超大血条与连击数字（`battle-fx` 组件已有基础）。
**差异化最强**，但**需要新素材**（金属边框、斜切底板），且斜切在小屏信息密度下很难排；对 K12 教育气质也有偏离风险。

### 对比

| | 天空塔 | 战斗手账 | 街机 HUD |
|---|---|---|---|
| 与现有结构契合 | 高 | 中 | 中 |
| 复用现有资产 | **高（零新素材）** | 高 | 低（需新素材） |
| 解决"四页各玩各的" | **强** | 中 | 中 |
| 实现成本 | 中 | 低 | 高 |
| 与低龄教育气质 | 高 | 中 | 偏低 |
| 风险 | 关卡页需重排 | 爽感不足 | 素材 + 排版 |

## 3. 推荐方案详设：天空塔

### 3.1 视觉语言五条规则（这是"想法"的核心，比配色重要）

1. **一切向上。** 页面主轴线是垂直的，不做横向卡片流。进度、层级、成长都用"高度"表达。
2. **三层景深。** 每屏最多三种纵深：远景（云/天空渐变）、中景（塔层/云台）、近景（卡片/立绘）。用**透明度 + 缩放**区分，不用新颜色。
3. **卡片只在近景。** 中景和远景不允许出现白卡，否则纵深立刻塌掉（这是现在"每页都像表格"的原因）。
4. **一个主操作。** 每屏只有一个橙色实心按钮，其余全是白底/描边。
5. **图标与 emoji 分工。** 功能入口用 `art/` 图标（已有 12 玩法 + 8 UI 按钮），**情绪表达**才用 emoji（胜利、连击、提示）。不再用 emoji 当功能图标。

### 3.2 令牌表（只列与视觉方向相关的，完整版并入 `app.wxss`）

```text
层级（新增，这是天空塔的关键）
  --z-far    远景：天空渐变 / 云海        （不承载交互）
  --z-mid    中景：塔层 / 云台 / Boss 剪影  （弱交互）
  --z-near   近景：卡片 / 按钮 / 立绘       （全部交互）

颜色（沿用现有高频值，不发明新色）
  --sky-top #4a9fe8   --sky-mid #8dbdf0   --sky-bot #d8efff
  --battle-1 #3b2a5e  --battle-2 #c98ab8   （对局页深色战场，已有）
  --surface #ffffff   --surface-2 #eef2f8
  --ink #3a3a5c       --ink-sub #5c7f9e    --ink-weak #8a9bb5
  --cta #ffb703       --cta-deep #d97c00
  --win #3fbf5f       --gold #ffd166       --danger #ff5a5a
  --line rgba(58,58,92,.10)

字号（6 档，取代现在 45 档）
  20 / 24 / 28 / 32 / 40 / 52
  特大数字（星级、连击）允许 72 / 96，登记为 --fs-display

  --sh-near  0 8rpx 0 rgba(0,0,0,.10)     近景卡片（硬阴影，保留现有手感）
  --sh-float 0 12rpx 32rpx rgba(0,0,0,.14) 浮层/弹窗（软阴影）
  ⚠️ 中景/远景不允许加阴影
```

### 3.5 对局页（唯一的深色场景）

- 背景 `--battle-1 → --battle-2`（暗紫，已有 token），Boss 立绘占屏 38~40%
- HUD 收到 **3 个胶囊**（关卡 / 血量 / 连击），现在 game 页是 8 个元素挤一行
- 字母面板留白加大，按钮 ≥ 96rpx（现在 56rpx 的 `.gs-bullet` 偏小）
- 结算弹层沿用 `settle-pop` 组件

### 3.6 素材：需要补什么、不需要什么

| 需要 | 说明 |
|---|---|
| 云层/云台 | **CSS 即可**（多层 `border-radius` 椭圆 + 半透明白），不入包体 |
| 楼层条装饰 | CSS 渐变即可 |
| 塔的远景插画 | 可选。要的话 1 张 750×900 透明底 PNG，走 CDN `art/ui/` |

| 不需要 | 理由 |
|---|---|
| 新立绘 | 现有 56 张够用 |
| 新玩法图标 | `art/game-icons/` 已有 12 个 |
| 新按钮图 | `art/ui-buttons/` 已有 8 个 |
| 新 tab 图标 | 包内 21.6KB / 200KB，余量充足，暂不动 |

## 4. 分四期落地（每期可独立验收）

| 期 | 内容 | 验收标准 | 预估 |
|---|---|---|---|
| **P0** | 护栏 + 令牌 | `check-design-tokens.js` 上线：色值 ≤24、字号 ≤6 档、圆角 ≤3 档、`var()` 覆盖率 ≥80%；全站机械替换 | 3~5 天 |
| **P1** | 首页 + 结算（天空塔） | 一屏 ≤5 块；截图回归；元素计数 | 3~4 天 |
| **P2** | 关卡页（塔的剖面）+ 对局页（深色战场） | 30 关可一屏浏览；对局 HUD ≤3 胶囊 | 4~5 天 |
| **P3** | 其余页 token 化（不动布局） | 护栏通过 | 3~4 天（可交他人） |

**顺序不可调**：P0 先行。原因见 §0.2——过去 19 天证明了没有护栏的规范会立刻漂回去。

**护栏清单：**

| 护栏 | 检查 |
|---|---|
| `e2e/check-design-tokens.js`（新） | 色值/字号/圆角档位、`var()` 覆盖率 |
| `e2e/check-wxss.js`（已有） | 禁止深色模式媒体查询、height 与 line-height 一致 |
| `e2e/check-assets.js`（已有） | 包内图片 + 音频 ≤200KB、打包目录纯净 |
| `e2e/check-taps.js`（已有） | 可点元素必须绑事件 |
| 截图回归 | 4 个核心页逐页存档到 `e2e/reports/shots/` |

## 5. 其他建议（与主题无关，但值得一起做）

1. **玩法页的 10 种主题渐变，登记成正式 token。** 现在 clock 橙 / hanoi 粉 / maze 蓝灰 / memory-grid 深蓝各自写死，属于"无主色值"。要么登记为 `--theme-clock` 等玩法主题变量，要么统一回天空蓝。
2. **`.chip` / `.list-row` / `.stat-row` 抽成全局件。** 排行榜、错题本、每日一题、学习页现在各写一遍"图标+标题+副标题+箭头"的行，四份实现四种间距。
3. **emoji 退出功能位。** 建立一张对照表：功能入口 → `art/` 图标；情绪/反馈 → emoji。这一步能消掉最明显的"廉价感"。
4. **补 `disabled` 态。** 现在 49 页里只有 1 处实现。avatar 的解锁按钮甚至没校验 `canUnlock` 就能点。
5. **修 6 个 P0 布局 bug**（见上一轮审查：klotski 裁切、result 三按钮挤压、两页缺安全区等），它们与重构无关，可以立刻修，不必等视觉定稿。
