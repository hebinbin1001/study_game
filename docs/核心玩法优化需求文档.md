## 一、背景与目标

当前核心玩法（竖屏打怪补字）链路完整、工程实现扎实，但存在**数值规则自相矛盾**与**学习闭环未接通**两类问题。本文档汇总 13 条优化需求，按优先级排序，供开发排期。

目标：

1. 让星级评定恢复区分度，成为"打得好不好"的有效度量；
2. 把已具备的错题 / 艾宾浩斯能力接入主玩法，形成"越玩越会"的自动复习闭环；
3. 补齐已拍板但未实现的功能（暂停）；
4. 提升题目质量与形态差异，减少"10 关同一道题"的重复感。

**范围约束（重要）**：除明确标注外，所有需求**不得改动成绩上报口径**（`score = 答对数 × 10`、星级由服务端按正确率推导的防伪设计必须保留）。

## 二、现状核心循环（供开发对齐）

```
关卡地图（学段 + 题型分类）→ 对局（选经典/Boss/极速）
  → 怪兽带挖空题下沉，点 4 选项补全
  → 答对：炮弹命中 +10 分 / 连击 +1 / 进入 0.7s 死亡动画
  → 答错：怪兽逼近 0.6s → 扣 1 命 → 公布答案 → 下一题
  → 10 题答完 → 按正确率评星（90/70/40）→ 写本地星级档 + 上报成绩 + 段位同步
  → 返回关卡地图，逐关解锁（上一关 ≥1 星）
```

关键参数现状：

| 参数 | 当前值 | 位置 |
|---|---|---|
| 每关题数 | 10 | `miniprogram/utils/constants.js:77` |
| 初始命数 | 3 | `miniprogram/utils/constants.js:78` |
| 怪兽下沉速度 | 13 px/秒 | `miniprogram/utils/constants.js:79` |
| 答错逼近时长 | 0.6 秒 | `miniprogram/utils/constants.js:81` |
| 星级阈值 | 90 / 70 / 40 | `miniprogram/utils/constants.js:45`、`server/constants.js:36` |
| 极速倒计时 | 6 秒 | `miniprogram/game/config.js`（`RUSH_SECONDS`） |

## 四、P0 需求详述

### R1 星级档位可达性修复

**优先级**：P0（最高）

**现状问题**

三条规则叠加后互相矛盾，导致 **1 星在数学上不可达**：

1. 初始命数 3，命扣到 0 立即判负且不写星级档（`game/engine.js:245-250`）；
2. 通关条件是答满 10 题（`game/engine.js:407-410`）；
3. 星级阈值 90 / 70 / 40（`miniprogram/utils/constants.js:45`，服务端同）。

推导：通关最多只能错 2 题 → 正确率只可能是 100% / 90% / 80% → 结算**仅有 3 星和 2 星两种结果**，1 星区间（40%~69%）永远取不到，0 星通关同样不可能。副作用：星级区分度只剩两档；关卡解锁条件"上一关 ≥1 星"等价于"通关过"，形同虚设。

**需求描述**

调整命数与阈值，使三档星级都落在可达区间内。以下两个方案二选一，由产品确认：

- **方案 A（推荐 · 已实施）**：命数 3 → **5**，阈值 90 / 70 / 40 → **90 / 70 / 60**
  可达分布：错 0~1 题 = 3 星，错 2~3 题 = 2 星，错 4 题 = 1 星，错 5 题 = 失败。
  > 勘误：本节初稿把 2 星阈值写成 80，但"错 3 题 = 70%"在 80 阈值下只能得 1 星，
  > 与同段给出的分布（错 2~3 题 = 2 星）自相矛盾。已按预期分布修正为 70，
  > 并在 `miniprogram/utils/__tests__/stars-reachable.test.js` 中固化逐档映射作为护栏。
- **方案 B**：命数 3 → **4**，阈值 90 / 70 / 40 → **90 / 80 / 70**
  可达分布：错 0~1 题 = 3 星，错 2 题 = 2 星，错 3 题 = 1 星，错 4 题 = 失败。

**实施记录（2026-09-11）**

| 项 | 内容 |
|---|---|
| 状态 | ✅ 已实施并验证 |
| 采用方案 | 方案 A（5 命 + 90/70/60） |
| 改动文件 | `miniprogram/utils/constants.js`（initLives 3→5、阈值）、`server/constants.js`（阈值同步）、`miniprogram/pages/game/game.js`（新手引导文案与初值随配置联动）、`game/config.js`/`game/state.js`（注释） |
| 新增护栏 | `miniprogram/utils/__tests__/stars-reachable.test.js`——独立复算结局规则，断言三档星级全部可达、通关至少 1 星、判负不计星、最低阈值不高于通关可达最低正确率、前后端阈值完全一致 |
| 测试适配 | `constants.test.js`（阈值边界）、`engine.test.js`（命数断言改为随配置联动）、`e2e/verify-game.js`（命数断言随配置联动并新增 5 心断言） |
| 验证 | `node e2e/run-all.js` 全量通过（静态 3 + 单元 1 + 端到端 6） |

**验收标准**

1. 构造 0 / 1 / 2 / 3 / 4 题错误的对局，结算星级符合方案 A 或 B 的分布；
2. 前端 `miniprogram/utils/constants.js` 与服务端 `server/constants.js` 阈值**保持完全一致**；
3. 结算页展示星数、本地星级存档、`/api/score` 落库星级三者一致；
4. `npm test` 全绿，其中 starsByRate 相关断言同步更新。

**涉及文件**：`miniprogram/utils/constants.js`、`server/constants.js`、`miniprogram/game/engine.js`、`miniprogram/game/state.js`、`pages/result/result.js`

**风险与备注**：历史星级存档不回改（旧存档仍有效，表现为老关卡更容易补满三星）；服务端阈值若漏改，会导致前端展示星级与云端统计不一致。

### R2 错题接入主玩法抽题（自动复习）

**优先级**：P0（本批**业务价值最高**的一条）

**现状问题**

错题复习能力已经具备，但主玩法完全没用上：

- 前端 `utils/ebbinghaus.js` 已实现熟练度 / 复习间隔 / 到期判定，单测通过；
- 后端 `wrong_records` 表已有 `mastery`、`reviewCount`、`nextReviewAt` 字段；
- 接口 `GET /api/wrong/list`（`server/routes/wrong.js:98`）已支持"待复习（未掌握）"口径；
- 但 `pages/game/game.js` 的 `getNextItem` 只调用 `dict.randomItem` / `dict.randomItemByGroup` 纯随机抽题，**从不读取错题**。

结果：错题只在你主动进入错题本时才复习，主玩法与学习数据脱节。

**需求描述**

1. 对局开始前（或开局时）拉取登录用户的待复习错题列表，缓存到本局运行时状态；
2. 本局抽题时，以 **20%~30% 概率**优先出待复习错题，其余仍为随机抽题；
3. 错题题型与当前关卡分类不匹配时跳过（分类关卡只能出该类题目）；
4. 未登录 / 游客 / 接口失败 → 回退为现有纯随机逻辑，不报错、不阻塞对局。

**验收标准**

1. 登录用户存在待复习错题时，连续 5 局（每局 10 题）统计错题出现比例落入约定区间（允许边界波动）；
2. 同一局内不重复出题（沿用 `_usedItems` 去重）；
3. 游客、未登录、接口失败三种情形下，行为与当前版本完全一致；
4. 分类关卡下不会混入非本分类的错题。

**涉及文件**：`pages/game/game.js`（`getNextItem`）、`utils/dict.js`（新增按指定池抽题入口）、`utils/ebbinghaus.js`

**备注**：后端 `wrong_records.question` 已存 `{type, q, a, hint}` 快照，结构与前端 WordItem 对齐，可直接用于出题。

### R3 答错反馈延长 + 选项高亮

**优先级**：P0

**现状问题**

答错后仅停留 0.6 秒（`miniprogram/utils/constants.js:81` 的 `approachTime`）就切换下一题。虽然画布上会把正确字符用红色填入空槽、提示行也会写"正确答案是 X = 释义"，但 0.6 秒对低龄玩家来说一闪而过。同时**底部选项按钮没有任何高亮**，玩家视线容易停在按钮上而非怪兽身上，纠错效果打折扣。

**需求描述**

1. 答错停留时长由 0.6 秒延长至 **1.2~1.5 秒**；
2. 选项区把**正确选项标绿**、**被点错的选项标红**；
3. 保留现有文案与画布红色填空反馈；
4. 动画期间点击继续不响应（沿用现有状态机拦截）。

**验收标准**

1. 答错后停留 ≥1.2 秒才出新题；
2. 正确选项呈现绿色态、误选项呈现红色态，下一题自动复位；
3. 反馈期间误触不产生额外扣命或计分。

**涉及文件**：`miniprogram/utils/constants.js`、`miniprogram/game/engine.js`（`_failQuestion` / `_update`）、`pages/game/game.js` 与 `game.wxml` / `game.wxss`（选项态类名）

### R4 结算页本局错题回顾

**优先级**：P0

**现状问题**

`docs/需求对齐-6合1.md` 已将"结算页本局错题列表（可查释义）"列为 P0，但当前 `pages/result/result.wxml` 只有星级大展示与四格统计。引擎侧其实已经在每次答错时通过 `onWrong` 回调把错题交给页面层（`game/engine.js` 的 `_failQuestion`），但 `pages/game/game.js` 仅用它上报后端，**没有传给结算页**。

**需求描述**

1. 结算页新增"本局错题"卡片，列出本局答错的词条：题目 + 正确答案 + 释义（有例句 `ex` 时一并展示）；
2. 无错题时隐藏该卡片，不留空白；
3. 失败态同样可查看。

**验收标准**

1. 本局答错 N 题时，结算页错题卡条目数为 N；
2. 每条包含题目、正确答案、释义；带例句的词条展示例句；
3. 本局全对时卡片不出现且不影响页面布局；
4. 失败态进入结算页也能看到错题卡。

**涉及文件**：`pages/game/game.js`（收集数组并中转）、`pages/result/result.js` / `.wxml` / `.wxss`

**备注**：URL 查询参数长度有限，建议用 `storage` 临时中转（如 `ww_last_wrong`），跳转后读取并清理。

### R5 对局暂停按钮（已拍板未实现）

**优先级**：P0

**现状问题**

`docs/需求对齐-6合1.md` 第九节第 4 条已拍板："对局提供暂停；暂停时遮罩覆盖并隐藏关卡画面（防止偷看题目与计时）；极速模式暂停时倒计时须停表；提供继续 / 返回"。但 `pages/game/game.wxml` 的 HUD 只有命数 / 得分 / 题号 / 声音，**暂停未实现**。

**需求描述**

1. HUD 增加暂停按钮；
2. 暂停时显示遮罩并覆盖画布（题目不可见），计时全部停止；

**验收标准**

1. 暂停期间画布被遮罩覆盖，题目与计时信息均不可见；
2. 极速模式暂停时序倒计时不减少，恢复后从剩余时间继续；
3. 暂停→返回不产生成绩上报、不误判通关或失败；
4. 频繁暂停 / 恢复不会造成主循环重复注册（引擎已有幂等 resume 逻辑，需回归验证）。

**涉及文件**：`pages/game/game.js`（复用现有 `_rushStop` / `_rushResumeIfIdle` 模式）、`game.wxml` / `game.wxss`

## 五、P1 需求详述

### R6 关卡难度曲线参数化

**现状问题**：`miniprogram/game/config.js` 头部注释声明"关卡难度参数化（REQ-GAME-3）"，但实现中下沉速度、命数、题数均为全局常量，`level` 参数只用于拼装存档 key。**第 1 关与第 10 关难度完全相同**，10 关体验高度重复。

**需求描述**：建立按"学段 + 关卡"取值的难度表，至少覆盖 —— 怪兽下沉速度、初始命数、选项个数（3 → 4 → 5）、极速倒计时秒数；同一学段内第 1~10 关须有可感知的难度爬坡。

**验收标准**：

1. 产出一张难度参数表（文档形式）并在代码中实现取值函数；
2. 相邻关卡至少 1 个参数递增；
3. 第 10 关明显难于第 1 关（可量化，例如下沉速度提升 ≥30%）；
4. 不影响计分口径与上报字段。

**涉及文件**：`miniprogram/game/config.js`、`game/state.js`、`game/engine.js`、`pages/game/game.js`

**备注**：与 R10（分学段调参）建议合并实现，共用同一张参数表。

### R7 表现分（连击 / 速度奖励，仅展示）

**现状问题**：`score` 恒等于答对数 × 10，速度与连击均不计分 —— 结算页的"得分"与"正确率"表达的是同一信息，属于冗余展示；"最高连击"没有任何实际后果，正反馈缺位。

**需求描述**：

1. 结算页展示"表现分"= 基础分 + 连击奖励 + 速度奖励，**纯展示**；
2. 玩法内连击给予非分数回报，例如连对 5 题获得一次"护盾"可抵一次失误；
3. 结算页对奖励规则给出简短说明。

**验收标准**：

1. 表现分仅在结算页展示，不写入 `/api/score` 的 `score` 字段，不影响星级；
2. 服务端仍按答对数推导分数（防伪口径不变），冒烟验证通过；
3. 护盾生效时正确扣减、无护盾时不改变原有扣命逻辑。

**风险**：**严禁**将表现分写入上报 `score`，否则与 `server/routes/score.js` 的防伪推导冲突。

### R8 三种形态规则差异化

**现状问题**：经典 / Boss 狂潮 / 极速竞技的判定、计分、节奏骨架完全一致；Boss 的血条本质就是"答对进度条"，玩家难以感知"换了一个玩法"。

**需求描述**：为每个形态增加至少一条**真实玩法规则**：

- Boss 狂潮：设置"弱点部位"，连击命中弱点造成更高伤害（血条掉得更快）；
- 极速竞技：剩余时间折算为奖励；
- 经典对战：保持稳定节奏作为基准形态。

**验收标准**：

1. 三种形态在结算表现上可明确区分；
2. 判定与计分口径保持不变，或经产品确认后两端统一调整；
3. 形态选择记忆（`ww_mode`）继续生效。

**前置**：需产品确认形态差异化方向后再开发。

### R9 干扰项质量提升

**现状问题**：`miniprogram/game/question.js` 的 `genDistractors` 对汉字干扰项优先使用形近字映射（做法正确），但当形近字不足时会从"整个学段词库的所有字"中随机抽取，仍不足还会落到兜底池 `['啊','的','了','是','在','有','和',...]` —— 在成语题中出现"啊、的"这类明显不可能选项，虽不影响答对，但练不出辨字能力。英文元音题的干扰项则固定取自其余 4 个元音，题型模式单一。

**需求描述**：

1. 汉字干扰项按 **形近字 > 同音字 > 同部首 > 同结构 > 同学段高频字** 的优先级生成；
2. 成语 / 词语题优先取同类词的同位置字（干扰项本身也是成语字，更具迷惑性与教学价值）；
3. 移除虚词兜底池，兜底改为同学段词库；
4. 英文题挖空位置轮换（元音 / 辅音 / 首字母），避免"永远挖元音"。

**验收标准**：

1. 抽样 100 道题人工复核，无"明显不可能"的干扰项；
2. 4 个选项两两不同，正确答案恰好出现一次；
3. `question.test.js` 全绿并补充新规则的用例。

---

### R10 分学段调参（命数 / 倒计时）

**现状问题**：极速倒计时固定 6 秒（`RUSH_SECONDS`），命数固定 3，对幼儿园与小学低年级偏紧（读题 + 看 4 个选项的时间都不够）。

**需求描述**：极速倒计时与初始命数按学段分档，建议示例：幼儿园 10 秒 / 5 命，小学 8 秒 / 4 命，初高中 6 秒 / 3 命。与 R1、R6 的参数表统一实现。

**验收标准**：不同学段进入同一关卡时，实际生效参数与档位表一致。

## 六、P2 需求详述

### R11 例句渲染（数据已支持）

**现状问题**：`utils/parser.js` 与 `utils/validator.js` 已支持词库第 6 段 `ex` 例句字段并透传，`docs/CHANGELOG.md` 也标注"渲染展示后续做"，但**全项目目前没有任何地方渲染例句**。

**需求描述**：答对 / 答错回执与结算页错题卡在词条带例句时展示例句；无例句时优雅降级，不占位。

**验收标准**：导入带 `ex` 字段的词条后，游戏内回执与结算页均能展示例句；不带 `ex` 的词条表现与当前一致。

## 七、不建议改动的部分（现有设计较好，建议保持）

1. **题型分类关卡**（可只练成语 / 歇后语 / 填空）—— 学习针对性强；
2. **自定义关卡**：10 题一组 + 分享码 + 公开广场 —— UGC 链路完整；
3. **防剧透提示**：`safeHint` 会把泄露答案的 hint 替换为题型引导语；
4. **离线可玩**：本地词库 + 待上报成绩队列（`flushPendingScores`）；
5. **服务端推导分数防伪**：`score = 答对数 × 10`、星级由服务端按正确率推导；
6. **O1 全机型自适应方案**：Canvas 等比缩放居中 + 安全区适配。
