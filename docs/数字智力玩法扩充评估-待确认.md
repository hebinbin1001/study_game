## 〇、结论先行

1. **该往这边加。** 数字智力已上线 **8 款 / 242 个关卡节点**，玩法数已经超过闯关线的 7 款；而存量评估的结论是**数字智力的难度结构远比题库玩法健康**（华容道最少步数 8→100 单调递增、24 点按「是否必须用中间分数」分真档次），题库玩法那边则撞上了 **13 题数学天花板**。**继续加题库玩法收益递减，加数字智力是更好的方向。**
2. **推荐先加 2 款：`找规律`（数列推理）+ `算术迷宫`。** 都是**零素材**、**关卡程序生成**（不需要人工出题 + 唯一解校验）、可无限出题、教学价值明确。
3. **汉诺塔排第三，不是第一。** 它最容易单测（最少步数闭式解 2ⁿ−1），但 3 根柱子的解法唯一、学会后每关都是同一套动作，**可玩深度低**。若要做，建议做成「最少步数挑战」而不是 30 关长线。
4. **数字推盘（8-puzzle）有重复度风险**：它和华容道都是「滑动方块到目标位」，观感接近，加之前要先想清楚怎么区分。
5. **加到 10 款后，建议顺手收掉「第 5 个底部 tab」这个悬置决策**——8 款时不做 tab 是对的，10 款时二级分段会变长。

## 三、筛选标准（这个项目特有的三条硬约束）

1. **零素材**。包内图片/音频总量 ≤ 200KB（现在 20.8KB，但光新出的 tab 图标就要吃掉 59KB）。华容道当年能加进来，就是因为「**零图片，纯 CSS 方块，只增 20~30KB JS**」。
2. **关卡能程序生成**。固定关卡表要人工出题 + 可达性/唯一解校验（`klotski-levels.test.js`、`math24-levels.test.js` 那种），成本高一个量级。
3. **不与现有 8 款撞机制**（见 §四「重复度」一列）。

## 四、候选评估

### 4.1 汇总表

| 评级 | 玩法 | 能力维度 | 关卡来源 | 素材 | 重复度 | 可玩深度 |
| --- | --- | --- | --- | --- | --- | --- |
| ★★★★★ | **找规律**（数列推理） | 数感 / 归纳 | 程序生成，无限 | 零 | 无 | 高（可无限出题） |
| ★★★★☆ | **算术迷宫** | 口算 × 空间 | DFS 程序生成 | 零 | 与口算冲刺共用"口算"，但玩法完全不同 | 高（随机迷宫） |
| ★★★★☆ | **汉诺塔** | 递归 / 规划 | 程序生成（盘数） | 零 | 无 | **低**（解法唯一） |
| ★★★☆☆ | **数字推盘（8-puzzle）** | 空间 / 规划 | 程序生成（随机盘面） | 零 | **与华容道接近** | 中高 |
| ★★★☆☆ | **时钟 / 时间推理** | 生活数学 | 程序生成 | CSS 表盘 | 无 | 中（偏教具） |
| ★★☆☆☆ | 数织 Nonogram | 逻辑推理 | **人工关卡表 + 唯一解校验** | 零 | 无 | 高 |
| ★★☆☆☆ | 数回 / 数桥 | 逻辑推理 | **人工关卡表** | 零 | 无 | 中 |
| ★★☆☆☆ | 推箱子 Sokoban | 空间 / 规划 | **人工关卡表 + 可解校验** | 零 | **与华容道同机制** | 高 |

**不建议加（换皮）**：数字消消乐 / 记忆翻牌（与「词义消消乐」「记忆矩阵」同构）、24 点变体、数独变体。

### 4.2 找规律 · 数列推理（推荐首选）

**规则**：给出一列数、挖掉 1~2 项，选出正确的补数。

**引擎** `game/sequence.js`（纯逻辑，无 `wx`）：
```js
makePuzzle(tier, rng)   // → { seq:[..], blanks:[idx..], ans:[..], options:[..4], ruleName }
```
- **题型族**（按 `tier` 递增）：等差 → 等比 → 交替（+2,+3,+2,+3）→ 平方数 → 二阶等差（差的差恒定）→ 斐波那契式递推
- **干扰项**：用「错规则」生成（把等差当成等比、把平方数当成等差数列）→ **教学意义最强的干扰**

**关卡**：程序生成，**不设上限**（照 `g2048` 的 `COUNTS = 0` 先例）。一关 10 题。

**难度**：`tier` 决定题型族（1~6 档），题内再按「挖空数 1→2」微调。

**星级**：按**正确率** 90/70/60 折星，直接复用 `challenge.starsByRightRate()` → **三档可达天然成立**（这是最省事、最不容易踩坑的口径）。

**零素材呈现**：数列用一行圆角方块（`view` + CSS）排成「数轴/串珠」，纯 CSS，不需要图片。

**单测要钉的不变量**：
- 生成的 `seq` 必须严格满足所声明的规则（用规则函数回算）；
- `options` 四项互不相同、且**恰好包含一个正确答案**；
- 干扰项**不等于**正确答案；
- `tier` 递增时题型族单调变难（不准出现高档位退回等差）。

**风险**：出题质量完全取决于题型族设计，若规则太单调会变成"刷题"。建议至少 6 个题型族 + 干扰项必须"像真的"。

### 4.3 算术迷宫（推荐次选）

**规则**：N×N 网格，从左上走到右下；每进一格要先答对一道口算门，答错退回上一格（或扣时）。

**引擎** `game/math-maze.js`：
```js
generate(size, gradeIdx, rng)  // → { grid, gates, start, goal, answerPath }
```
- 迷宫用 **DFS 回溯生成**（保证**必有解**，这是可测的不变量）
- 口算门复用现成的 `game/math-sprint.js` 的 `makeQuestion(elapsedMs, gradeIdx)` —— **注意它刚被修过一个 bug**（`gradeScale` 原来按 7 档写、初一~大学会回落，已修），新玩法直接用即可

**关卡**：程序生成，`COUNTS = 0`（不设上限）。

**难度**：网格 4×4 → 7×7 + 算式范围按学段（复用 `gradeScale`）。

**星级**：按**通关用时**或**错误次数**折三档（需自行证明三档可达，不能照抄正确率口径）。

**零素材**：网格与门全部 CSS。

**单测要钉**：
- 生成的迷宫**从起点到终点必有路径**（DFS 生成保证，用 BFS 复核）；
- 每道门的答案**唯一**、干扰项不含答案；
- 网格尺寸 / 算式范围随 `tier` 单调。

**风险**：与「口算冲刺」都依赖口算，营销话术上要讲清区别（限时抢答 vs 走迷宫）；另外走迷宫的交互（方向键 vs 点击相邻格）要做对，别做成"只能点不能滑"。

### 4.4 汉诺塔（可做，但**不要按它最容易测就排第一**）

**规则**：3 根柱子 N 个盘，大盘不能压小盘，把所有盘从 A 挪到 C。

**引擎** `game/hanoi.js`：
```js
newGame(disks)              // → { a:[{n}], b:[], c:[] }
canMove(state, from, to)    // 规则校验
move(state, from, to)       // → 新 state 或 null
isSolved(state, disks)
minMoves(disks)             // = 2 ** disks - 1（闭式解）
```

**优点**：最少步数有**闭式解**，单测可以钉得非常死（`minMoves(5) === 31`、递归解序列执行完必 `isSolved`）。

**缺点（为什么降到第三）**：3 根柱子的**最优解唯一**，小孩一旦理解递归，后续每一关都是同一套动作——**"可玩深度低"**。这跟"好不好测"是两件事，不该拿可测性当排序依据。

**若要做，建议这样收口**：
- 不做 30 关长线，做 **12 关左右**：「盘数 3→8」×「3 柱 / 4 柱（Reve's puzzle）」两种变体；
- 核心指标是**最少步数**（每关记录 best），比"通关"更有重复动机；
- 星级按「用了最少步数的倍数」折三档（需自行证明可达）。

### 4.5 数字推盘 8-puzzle（谨慎）

**规则**：3×3（或 4×4）滑块，把打乱的数字块复原成顺序。

**优点**：可解性有**逆序数奇偶判据**，单测能钉死"打乱后一定有解"（这是这类游戏最容易出的 bug——给出无解盘面）。

**为什么谨慎**：与**华容道**同为「滑动方块到目标位」。虽然目标不同（一个复原顺序、一个把曹操移出出口），但玩家观感接近，**重复度风险实打实**。若要做，得靠视觉/命题区分（例如做成"复原一张图"的拼图，但那需要素材，与"零素材"标准冲突）。

### 4.6 时钟 / 时间推理（可选）

认识钟面、算时间差、推算"再过 40 分钟是几点"。**小学课标重点**、零素材（CSS 表盘）、可程序生成。缺点是观感偏"教具"不偏"游戏"，且需要新写一个表盘渲染（比前两个多一块 UI 工作量）。适合放在"生活数学"子分类里。

### 4.7 明确不建议的

| 候选 | 不推荐理由 |
| --- | --- |
| 数织 / 数回 / 数桥 | 每关都要人工出题并保证**唯一解**，内容成本高一个量级；且认知门槛偏高，与"6~12 岁为主"的定位错位 |
| 推箱子 | 人工关卡表 + 可解校验成本高，且**与华容道同机制** |
| 数字消消乐 / 记忆翻牌 | 与现有「词义消消乐」「记忆矩阵」同构，纯换皮 |
| 24 点变体 / 数独变体 | 不是新玩法，是对现有玩法的追加深浅，不如直接给现有玩法加档位 |

## 五、排序与推荐

| 顺序 | 玩法 | 理由 | 预估工作量 |
| --- | --- | --- | --- |
| **1** | 找规律 | 零素材 + 无限出题 + 教学价值最高 + 复用正确率折星（三档可达免证明） | 约 2 天 |
| **2** | 算术迷宫 | 零素材 + DFS 保证有解 + 体验较新；口算门可复用 `math-sprint` | 约 2.5 天（含交互打磨） |
| 3 | 汉诺塔 | 最容易测，但可玩深度低 → 建议做成"最少步数挑战"而非长线关卡 | 约 1.5 天 |
| 4 | 数字推盘 | 经典，但要先解决与华容道的区分 | 约 2 天 |
| 5 | 时钟推理 | 课标点，但需要新写表盘 UI | 约 2 天 |

**建议先做 1 + 2。** 两者互补（归纳 vs 口算×空间）、都零素材、都程序生成、都不撞现有机制。做完数字智力到 **10 款**。

## 六、与「第 5 个底部 tab」决策的关系

`docs/当前未完成事项.md:241` 挂着：

> 数字智力类是否升成第 5 个底部 tab：**视内容厚度再定**；升级只需补两枚 tab 图标。

**现状判断**：当 8 款时不做 tab、只做玩法页内二级分段是对的（底部 4 个 tab 再切一刀会稀释「学习」）。
但**加到 10 款后**，玩法页的「🧠 数字智力」分段会有 10 张卡，纵向长度明显变长——**这时升 tab 的性价比开始成立**。

如果决定升 tab，需要额外做的：**两枚 tab 图标（选中/未选中，81×81）**。注意这批图标要进包，计入 200KB 预算（当前 20.8KB + 新 tab 图标 59KB = 约 80KB，仍安全）。

> 顺带：这次新出的 UI 素材里**已经有 4 枚彩色 tab 图标**（首页/玩法/学习/我的），但**没有数字智力那两枚**，若升 tab 需要补出。
