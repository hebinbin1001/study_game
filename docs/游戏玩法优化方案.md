# 玩法优化方案（2026-10-17 审计）

> 方法：读 `utils/challenge.js`（关卡表 / 参数 / 星级）、`utils/rank-ladder.js`（段位曲线）、
> `utils/skins.js`（皮肤解锁）、题库规模，并用脚本算了关键阈值。
> 结论按「影响大小」排序，**没有改任何数值**——涉及平衡的改动需要你拍板。

## 一、最要紧的一条：单学段玩家的天花板太低

**证据（脚本算的）**

| 项目 | 数值 |
|---|---|
| 一个学段主线满星 | 30 关 × 3 星 = **90 星** |
| 该学段宝箱全领 | 10 + 20 + 30 = **60 星** |
| 单学段理论总产出 | **150 星** → 段位 **黄金 VIII（26/81 级）** |
| 皮肤里的星数门槛 | 30 / 60 / 90 / 140 / 200 / 260 / 330 ⭐ |
| 皮肤里的段位门槛 | 白银 2 → 学神 9（对应 200 ~ 1187 星） |
| 段位满级（学神 IX） | **1187 星**（主线 14 学段全 3 星 = 1260，需 94% 满星率） |

**问题**：皮肤解锁曲线是按「14 个学段全玩一遍」设计的，但真实用户基本只玩自己那个年级。
一个三年级学生把本学段全部刷满，也只能到黄金段位，**钻石/星耀/王者/学神这 5 档皮肤永远解锁不了**。
这次 UI 重做把「皮肤收集」当核心动机（首页收集条、下一目标提示），如果一半以上皮肤不可达，动机是断的。

**建议（三选一，或组合）**

1. **改口径（推荐）**：皮肤解锁从「总星数/总段位」改成「当前学段进度 + 成就」。
   例如「本学段 30 关全通」「本学段 60 星」「连续 7 天」——单学段玩家也有完整收集线。
2. **加产出**：Boss 首通 +10 星、每日挑战 3 星、每周任务，把单学段月产出拉到 300+。
3. **降曲线**：段位后段从「每 3 级 +1 星」放成「每 5 级 +1 星」，满级降到约 900 星。

代价：1 要动 `skins.js` + `avatar-seed.js`（前后端一致）；2 要新增奖励配置；3 只动 `rank-ladder`（但已有玩家段位会跳变）。

## 二、同一学段内没有难度曲线

**证据**：`CYCLE = [shoot, match, wordBuild, link, idiom, snake]`，30 关循环 5 遍；
`paramsOf(grade, mode, level)` **只在 Boss 关看 level**，普通关参数只由「学段 + 玩法」决定。

结果：同一个学段里，第 1 关的消消乐和第 25 关的消消乐，**都是 8 对牌、3 条命**，只是题目换了。
玩家在第 25 关不会感到"我变强了/这关更难"，只有换玩法带来的新鲜感。

**建议**：按「该玩法在本学段的第几次出现」做小幅递进：

| 玩法 | 第 1 次 | 第 5 次 | 说明 |
|---|---|---|---|
| 字母拼词 / 成语拼字 | 6~8 题 | 10~12 题 | 已有 `count`，只需按 occurrence 递增 |
| 贪吃蛇 | 4 词 | 6 词 | 同上 |
| 消消乐 / 连连看 | 8 对 | 8 对 + **限时** | 棋盘固定 4×4 加不了牌，只能加时间压力 |
| 字母射击 | 10 题 | 10 题 + **干扰项/更快反击** | 题量固定，靠节奏加压 |

代价：`challenge.js` 加一层 occurrence 计算 + 单测；限时是新机制，需要 UI 配合。
风险：已有关卡参数会变（玩家重玩时手感不同），但存档只记星级，不会卡关。

## 三、3 星标准在不同玩法之间不等价

**证据**：
- 字母射击 / 拼词 / 成语：`starsByRightRate` → **正确率 ≥90% 即 3 星**（10 题可错 1 题）。
- 消消乐 / 连连看 / 贪吃蛇：`starsByLives` → 3 命玩法 **错 1 次就掉到 2 星**（0 容错）。

**影响**：同样"错一次"，射击还是 3 星，消消乐变 2 星。玩家会得出"消消乐三星很难"的结论，
而皮肤又按星数解锁 → 不同玩法的"性价比"不一样，刷星会集中到射击。

**建议**：统一成一种口径。两个方向：
1. **统一按错误次数**：3 星 = 0 错，2 星 ≤2 错，1 星 = 通关（射击 10 题 5 命也这么算）。
2. **统一按正确率**：把消消乐/连连看/贪吃蛇的命数提到 5，并按 `right/total` 折算。

代价：只动星级函数与结算页文案；已有玩家的历史星级不回改（不追溯）。

## 四、限时抢答不在主线轮换里

**证据**：`MODES` 有 7 款（含 `quiz`），但 `CYCLE` 只有 6 款，**没有 quiz**。
主线 30 关永远遇不到抢答，只能从「玩法页 → 限时抢答」单独进它自己的 30 关线。

**影响**：7 款主线玩法玩家只经历 6 款；抢答的曝光完全依赖玩法页。

**建议**：`CYCLE` 加 `quiz`（7 款轮换，第 30 关仍覆盖为 Boss）。
**风险**：改轮换会改变每一关对应的玩法 —— 已有玩家「第 N 关已通」的星级还在，
但点进去玩法变了。要么接受（关卡本来就叫"挑战第 N 关"），要么按版本号只对新玩家生效。

## 五、重玩同一关题目完全一样

**证据**：`seedOf(grade, level)` 固定种子 → 同一关每次进去题面、面板顺序都一样。
这是刻意设计（刷星公平、好友打同一套题），但副作用是**背答案就能刷 3 星**，
而且刷星过程机械重复。

**建议**：首通保持固定种子；**重玩时**按 `seed + 重玩次数` 换一组题（结算仍取历史最佳星）。
分享/同题场景继续用固定种子（分享链接里带 seed）。

## 六、结算页缺「差一点」的钩子

**证据**：`result` 页只展示星级与正确率，没有"距下一星还差多少"。
而星级是三档硬阈值（90/70/60），差 1 题就从 3 星掉 2 星，玩家不知道自己差在哪。

**建议**：结算页加一行动态文案：
- 差 1 题 3 星 → 「再答对 1 题就是 3 星 ⭐⭐⭐」
- 差 2 题 2 星 → 「再答对 2 题升 2 星」
- 失败 → 「答对 6 题就能通关，你答对了 5 题」

代价：纯前端文案，**零风险**，对重玩率提升通常最直接。

## 七、建议的执行顺序

| 优先级 | 事项 | 代价 | 是否需要拍板 |
|---|---|---|---|
| P0 | ⑥ 结算「差一点」提示 | 0.5 天，纯 UI | 不需要，可直接做 |
| P0 | ③ 统一 3 星口径 | 1 天，含单测 | **需要**（选按错次还是按正确率） |
| P1 | ② 同玩法难度递进 | 1.5 天 | 需要（限时机制要不要上） |
| P1 | ① 皮肤解锁改口径 | 1~2 天 + 后端一致 | **需要**（这是产品方向） |
| P2 | ⑤ 重玩换题 | 0.5 天 | 需要（会影响"同题分享"的心智） |
| P2 | ④ 抢答进主线 | 0.5 天 | **需要**（老玩家关卡玩法会变） |

## 九、已落地（2026-10-17 用户拍板）

**③ 3 星统一按正确率** —— 已实现；其余五项（皮肤口径 / 难度曲线 / 抢答进主线 / 重玩换题 / 差一点提示）按用户要求暂不动。

换算口径：

| 玩法 | 计数单位 | 正确率公式 | 8 对牌 / 5 词下的实际档位 |
|---|---|---|---|
| 消消乐 | 配对对数 | (总对数 − 错配次数) / 总对数 | 0 错 3 星、1~2 错 2 星、3 错 1 星 |
| 连连看 | 配对对数 | (总对数 − (3 − 剩余命)) / 总对数 | 同上 |
| 贪吃蛇 | 词 | 拼完词数 / (拼完词数 + 错误次数) | 0 错 3 星、1 错 2 星、2 错 1 星 |

说明：
- `starsByLives` 保留导出（历史单测在用），但已标 `@deprecated`，新玩法不得再用；
- 规则改为「命耗尽 = 本局失败 0 星」不变，正确率只在**通关**时参与折算；
- 新增护栏 `challenge.test.js`：match / link / snake 不得再出现 `starsByLives`；
- 历史星级不追溯（已存的 3 星不会因为新口径被降）。

修正后的实际影响：以 8 对牌为例，**2 次错配从「1 星」变为「2 星」**；
1 次错配仍是 2 星、0 错仍是 3 星 —— **3 星门槛不变，只是中段变宽容**，
与射击「10 题错 1 题仍 3 星」的体感拉齐了。
