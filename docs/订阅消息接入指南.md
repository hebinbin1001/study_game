# 订阅消息接入指南（2026-10-28）

> 面向：要在公众平台申请模板、在云托管配环境变量的自己。
> 代码已经写完并在工作区（未提交），**模板 ID 一到就能跑通**；模板没到之前所有发送都会被静默跳过，不会污染主流程。

---

## 一、先记住三条硬规则

| 规则 | 具体 | 对设计的影响 |
|---|---|---|
| 教育类目**只能用一次性订阅** | 长期订阅（发一次管终身）只开放给金融、医疗、政务、民生等少数类目 | 用户每点一次「允许」只换 **1 条**下发额度，用完就没了 |
| 弹窗**必须由用户点击触发** | 不能进页面自动弹，不能放在 `setTimeout` / 异步回调里 | 订阅入口必须挂在具体按钮上（本项目挂在「🔔 好友应战时提醒我」） |
| 微信**不校验内容**，只校验额度 | 有没有额度看 openid 在它那边还有没有票 | 额度用完返回 `43101`，这是正常业务结果，不是故障 |

推论：**订阅是一张一张攒的票，不是开关**。所以入口要放在用户「当下就想要这个提醒」的位置，冷弹（进页面就弹）同意率极低，还会被用户在设置里永久拒收。

---

## 二、后台申请模板（5 步）

1. 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 左侧「功能」→「订阅消息」
2. 进「公共模板库」，按类目（教育）筛选，搜关键词：**学习提醒 / 打卡提醒 / 任务提醒 / 课程提醒**
3. 选中模板，看它的**字段列表**。本项目需要三个字段：

   | 语义 | 建议类型 | 例子 |
   |---|---|---|
   | 谁 | `thing` | 小明 |
   | 结果 / 事项 | `thing` | 8/10 题 · 你赢了 |
   | 时间 | `date` | 2026年10月28日 22:35 |

   找不到三个字段的模板也行，两个（`thing` + `date`）就能用，改 `server/subscribe.js` 的 `build()` 即可。
4. 点「添加」。部分模板允许在限定额度内替换关键词，**替换时保持类型不变**（`thing` 换 `thing`）。
5. 到「我的模板」复制 **模板 ID**（一长串字母数字，与 AppID 绑定，换 AppID 就失效）。

### 字段格式硬约束（写错就是 `47003`，微信不会告诉你哪个字段错）

| 类型 | 上限 | 说明 |
|---|---|---|
| `thing` | **20 个字符** | 汉字、数字、字母、符号都可以 |
| `phrase` | **5 个汉字** | 只能是汉字 |
| `date` | 年月日，可带 24 小时制时间 | `2026年10月28日 22:35` 或 `2026-10-28` |
| `time` | 24 小时制 | `22:35`，时间段用 `~` 连接 |
| `character_string` | 32 位 | 只能数字、字母、符号 |
| `number` | 32 位数字 | 只能是数字，可带小数 |

传参时 key 必须带模板里的序号：`thing1` / `thing2` / `date3`，不能只写 `thing`。

### 2.1 具体申请哪几个模板 → 见 `docs/订阅消息模板清单.md`

本节原来在这里写了一张模板清单，2026-10-28 拆成独立文档，原因是这张表要拿着去后台逐项对照着点，混在接入文档里翻找太麻烦。

一句话结论：**只申请 1 个，且不再扩充**（`WX_TPL_PK_ACCEPT`，字段 `thing` + `thing` + `date`）。其余 3 个场景都是定时扫库型，没有常驻实例就没有发送渠道 —— 2026-10-28 已决定不做常驻，所以那 3 个封存。

**加新场景的代码成本**：`server/subscribe.js` 的 `SCENES` 加一项 + `build()` 里写模板真实的 key，别的不用动（`ensure-tables` 的 `scene` 字段是字符串，不需要改表）。

## 三、云托管配置（两处）

### 3.1 环境变量（存模板 ID）

云托管控制台 → 服务 → 服务设置 → 环境变量，新增：

```
WX_TPL_PK_ACCEPT=<你复制的模板 ID>
```

| 变量 | 场景 | 没有它会怎样 |
|---|---|---|
| `WX_TPL_PK_ACCEPT` | 战帖被应战 → 通知发起人 | `GET /api/subscribe/config` 返回空对象，端上**不渲染订阅按钮**，服务端发送直接跳过 |

改完环境变量要**重新部署**才生效（容器重启时读）。

### 3.2 开放接口白名单（免 access_token 调用）

云托管控制台 → 服务 → 开放接口服务（若未开启先开启），把这条加到白名单：

```
POST /cgi-bin/message/subscribe/send
```

本项目的小程序码已经在用同一套机制（`getMiniCode` → `POST /wxa/getwxacodeunlimit`），所以这个入口应该已经开着，只要**多勾这一条**。

> 不配也能跑：代码会自动回落到「公网 https + access_token」，但那需要注入 `WX_SECRET`，而且 access_token 要自己维护过期。云托管内网通道是免费的，优先用它。

## 四、代码落点（已实现）

| 文件 | 作用 |
|---|---|
| `server/utils/wechat.js` | `sendSubscribe(touser, templateId, page, data)`：先走云托管内网（免 token），失败回落公网 https + access_token |
| `server/subscribe.js` | **场景表**（模板 ID 走环境变量）+ `sendScene()` + 授权/发送记账 |
| `server/routes/subscribe.js` | `GET /api/subscribe/config`（下发已配置的场景）、`POST /api/subscribe/grant`（记录用户点了允许） |
| `server/models/subscribe-grant.js` + `ensure-tables.js` | `subscribe_grants` 表：同意次数 / 成功 / 失败 / 最近错误。**启动自动建表**，不用手工跑 SQL |
| `miniprogram/utils/subscribe.js` | 端上封装：`warmup()` 预热配置、`ask(scene)` 主动弹订阅、`ensure(scene)` 顺路续票、`isAccepted()` |
| `miniprogram/pages/pk/*` | 「🔔 好友应战时提醒我」按钮（发起成功页 + 战帖详情页）+ 应战结果页的 `ensure` 续票按钮 |
| `server/routes/pk.js` | 应战成功后给发起人发通知，**不 await**，失败不影响对战响应 |

### 为什么按钮要做成「一次性动作」而不是开关

一次性订阅的额度在微信侧，服务端查不到余额。本地 `ww_pk_notify` 只记「点过」，用来换文案（已开启应战提醒），**不代表以后能一直收到**。用户想继续收，就得多点几次——这也是所有一次性订阅场景的现实。

### 「准永久」能做到什么程度（2026-10-28 补充）

先说结论：**微信没有永久订阅**。教育类目只能在「一次性订阅」里一天一张地攒。但有两个机制能让它接近可用：

1. **「总是保持以上选择」勾选框**。用户勾了之后，后续 `requestSubscribeMessage` 直接回 `accept`、**不再弹窗**，等于每次调用静默 +1 张票。这是官方允许的方式，代价是「必须由用户点击触发」这条规则仍然成立——所以仍然要有按钮。
   端上**查不到用户勾没勾**这个框，微信不返回。所以只能按「第一次会弹、之后靠用户勾选变得无感」来设计。
2. **多个充票点**。只有一个按钮时，用户不点就永远没票。于是分两种调用：

| 函数 | 场景 | 行为 |
|---|---|---|
| `ask(scene)` | 用户主动点「提醒我」 | 每次都弹，成功/失败都回话 |
| `ensure(scene)` | 搭在别的动作旁边顺路充一张 | **一天最多一次**；用户拒绝过就不再自动问；成功才提示，失败静默 |

`ensure` 的三条策略都是有原因的：

- **一天一次**：一人一天不会有多张战帖被应战，同一天多攒的票没有用；而每调一次都可能弹框。
- **拒绝过就记住**（`ww_sub_off_<scene>`）：微信对「拒绝并勾选总是保持」会一直回 `reject`，再问就是纯骚扰。用户主动点 `ask` 时不受这个标记限制——他要，就再问一次。
- **先落日期再弹框**：弹窗是异步的，用户连点两下会叠出两个框（iOS 上会卡住）。`fail` 时再把日期回滚，避免「今天再也补不上」。

当前挂载点：应战结果页（`role === 'opponent'` 时）—— 刚打完别人的战帖，是「那别人也该应战我」这个念头最强的时候。


### 记账表为什么不当闸门

`subscribe_grants` 只做观测（同意率、成功率、错误码）。发送时**不看余额直接发**：记账一旦漏记（网络抖动、前端没回调），把它当闸门就会永久漏发；而多发一次 API 调用几乎没成本。宁可多调，不可漏发。

## 五、联调与验收

### 5.1 配完先验配置有没有读到

```bash
curl -s https://<云托管域名>/api/health
# 登录拿 token 后：
curl -s -H "Authorization: Bearer <token>" https://<云托管域名>/api/subscribe/config
# 期望：{"code":0,"data":{"scenes":{"pk_accept":"你的模板ID"}}}
```

小程序里：进 PK 页 → 发起一张战帖 → 打完 → 「战帖已生成」页应该出现金色按钮「🔔 好友应战时提醒我」。
**按钮不出现 = 端上没拿到配置**（环境变量没配 / 没重新部署 / 拉配置失败）。

### 5.2 验证真的发出去了

用另一个微信号（或用开发者工具切账号）应战这张战帖。应战方提交成绩后：

- 发起人的微信「服务通知」里应该出现卡片，点开跳到 `pages/pk/pk?code=XXXX`；
- 服务端日志有一条 `[subscribe] 发送失败（pk_accept）：43101:...` 或成功（成功不打日志，看表）。

### 5.3 常见错误码

| errcode | 含义 | 怎么办 |
|---|---|---|
| `43101` | 用户没有订阅额度（没点允许 / 已用完） | **正常**。不用报错，也绝不能反复重试——重试也发不出去 |
| `47003` | 参数字段格式不对 | 对照 §二 的类型表逐字段核对；最常见的坑是 `thing` 超 20 字 |
| `40037` | template_id 非法 | 模板 ID 抄错，或与当前 AppID 不是同一个 |
| `40003` | openid 非法 | 用错了环境的 openid（测试号 / 另一小程序） |
| `43108` | 并发给同一粉丝发多条 | 本项目按事件单发，正常不会触发 |
| `-1` | 本项目自造：无可用调用凭证 | 白名单没配 + 没注入 `WX_SECRET`，见 §3.2 |

## 六、下一个场景（断档预警）需要补什么

代码骨架不用改，只加一个场景 + 一个触发器：

1. `server/subscribe.js` 的 `SCENES` 加 `checkin_break`（环境变量 `WX_TPL_CHECKIN_BREAK`）；
2. 端上在「今日任务完成」页挂一个按钮（时机比冷弹好：用户刚获得正反馈）；
3. **定时器**：云托管没有内置 cron，官方做法是在 Dockerfile 里装 `cron` + `curl`，容器启动时同时拉起 cron 与业务进程。
   ⚠️ 但容器会被缩到 0 —— **最小实例数必须 ≥ 1**，否则 cron 跟着停。这会产生常驻费用。

   > **2026-10-28 决定：不做常驻，所以这个场景封存。** 本节留作技术记录（换方案时不用重新调研），
   > 不要再按它去申请模板或装 cron。不用常驻的替代路径见 `玩法与功能缺失清单.md` §4.1 末尾。

`server/beijing-time.js` 里的时区基建是现成的（容器是 UTC，玩家按北京时间），直接复用。
