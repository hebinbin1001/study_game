## 一、为什么上次会翻车（本次设计的出发点）

上次的链路是「豆包出 4 张整屏效果图 → 直接照着写 CSS」，回滚了。实测对比设计稿与实现结果，差距不在配色：

| | 豆包设计稿 | 实际做出来 |
| --- | --- | --- |
| 一屏元素 | **5 个** | **11 个** |
| 主操作 | 橙色大按钮，一屏唯一 | 蓝色卡片，与 3 张白卡同权重 |
| 图标 | 插画风 | **emoji** |
| 角色 | 大立绘占屏宽 ~37% | 缩成 ~90px 小头像 |

**三个机制性原因（本次逐一解决）**

1. **信息架构没做决策**（→ 本文档第三章）。设计稿只画 5 个元素，真实首页有 11 个功能。实现时为了「不删功能」全留着、只换皮 → 必然还是卡片列表、主次消失。**视觉稿解决不了这个问题。**
2. **交付物形态错了**（→ 本文档第六章）。豆包给的是**整屏效果图**，不是分层素材：立绘没有独立透明底文件、效果图里的插画图标（火箭/日历堆/紫色怪兽）在现有 `art/` 里没有对应物。实现只能退回 emoji + 现有小图。
3. **缺设计系统**（→ 本文档第五章）。实测 48 个 wxss：`var(--*)` 使用次数 **0**（定义了 11 个 token，一次没用过）；硬编码色值 **1613 处 / 330 个不同色值**；27 种圆角、38 种字号。**「不满意但说不清哪里不对」的技术根因就是这个** —— 同一个语义有多个值，且没有统一入口。

## 二、目标与可量化验收

上次失败的一个原因是验收标准是「好看」。这次全部量化：

| 指标 | 现状（实测） | 目标 | 怎么测 |
| --- | --- | --- | --- |
| `var(--*)` 使用率 | **0%** | 主干页 100% / 全站 ≥ 80% | 扫 wxss 统计 var( 出现次数 |
| 不同色值个数 | **330** | **≤ 24** | 扫 wxss 去重 `#hex` |
| `border-radius` 取值 | **27 种** | **≤ 6 档** | 同上 |
| `font-size` 取值 | **38 种** | **≤ 8 档** | 同上 |
| `#fff` / `#ffffff` 混用 | 216 / 78 | 归一到 1 个 token | grep |
| 首页一屏常驻元素 | **11** | **≤ 6** | 数 wxml 顶层块 |
| 一屏主按钮数 | 3+（CTA/换关卡/入口） | **1** | 人工 + 截图回归 |
| 立绘最小可用尺寸 | 79×137（包内默认战士） | 3 档规范（见 §6） | 量图 |

> 这些指标可以做成 `e2e/check-design-tokens.js` 静态护栏（参照现有 `check-wxss.js` / `check-assets.js` 的写法），**改完能自动判红，不靠自觉**。

## 四、信息架构：首页（本轮核心）

### 4.1 现状（`pages/index/index.wxml` 实测 11 个顶层块）

```text
Header(品牌+声音) / Hero(立绘+昵称+段位+星) / 继续挑战 / 三入口 / 游客引导条 /
年级引导条 / 资产条(星·段位·连续) / 排行榜 / 今日目标 / 每日一题 / 推荐玩法
```

**症状**：① 信息重复（星数在 Hero 和资产条各出现一次，段位也是）；② 三个「今日」相关卡片分散（今日目标 / 每日一题 / 连续天数）；③ 排行榜与推荐玩法都是独立大卡，把页面拉长到 2 屏以上；④ 主操作「继续挑战」被夹在 Hero 和三个入口之间，不突出。

### 4.2 目标结构（一屏常驻 5 块 + 1 次级行 + 滚动区 1 块）

```text
① Header            品牌 + 声音开关（保留）
② Hero              ★强化：大立绘 + 昵称 + 段位徽章 + 星数   ← 资产条并入
③ 继续挑战          ★唯一主操作（橙色大按钮，占满宽）
④ 今日任务          今日目标 + 每日一题 + 签到 + 连续天数 合并为 1 张卡
⑤ 三入口            每日挑战 / 赛季 / 好友 PK（照设计稿）
⑥ 次级行（小 chip） 排行榜 · 换关卡 · 错题本
──────────────── 一屏以下（可滚动）────────────────
⑦ 推荐玩法          保留，但降到一屏之下
```

### 4.3 逐条决策表（**没有一个功能被删除**，这是关键）

| 现元素 | 决策 | 去处 | 理由 |
| --- | --- | --- | --- |
| Header | **保留** | ①  | 品牌与声音开关 |
| Hero | **保留 + 强化** | ② | 按设计稿做大立绘；点击进资料 |
| 资产条（星/段位/连续） | **拆解** | 星数、段位 → ② Hero；连续天数 → ④ 今日任务 | 消除信息重复，一屏省出一个卡位 |
| 继续挑战 | **保留 + 提权** | ③ | 全站第一主操作，橙色大按钮 |
| 今日目标 | **合并** | ④ | 与每日一题/签到本是同一件事 |
| 每日一题 | **合并** | ④ | 答完即签到，拆成两张卡是重复 |
| 排行榜 | **降级** | ⑥ 次级行 | 仍可点进，不再占一个整卡位 |
| 三入口 | **保留** | ⑤ | 设计稿也有，且是留存功能 |
| 推荐玩法 | **降级到滚动区** | ⑦ | 属"逛"的内容，不占首屏 |
| 游客引导条 | **保留（条件显示）** | ② 下方，仅游客可见 | 不影响登录用户体验 |
| 年级引导条 | **保留（条件显示）** | ② 下方，仅新用户可见 | 选过一次就不再出现 |

**收益**：常驻元素 11 → **5**（+1 次级行），达到设计稿密度；**功能零损失**；信息重复消除。

### 4.4 其余主干页的关键决策

| 页面 | 决策 |
| --- | --- |
| `level` 关卡 | 四层（学段 tab / 分类 chips / 进度卡 / 列表）压成两层：**学段选择器**（顶部，可折叠）+ **关卡列表**；分类 chips 移入「按题型练」二级入口 |
| `game` 对局 | 统一 HUD 组件：左上返回 / 中间关卡 / 右上我的战士徽章；状态胶囊一行不超过 3 个（现在 4~5 个会溢出，`dsgn7-math24.png` 里「已合并 0」已被截断） |
| ↑ **立绘位置（demo 实测得出，务必遵守）** | 立绘必须有一条**独立的留白带**（单独占位的「天空带」），**绝不能用 `position:absolute` 浮在内容上**。做 `demo/ui-redesign` 时第一版就是把战士绝对定位在右上角，结果**直接压住了第 4 张数字牌** —— 这就是「小头像怎么放都别扭」的机制性根因。竖屏里内容区是满宽的，任何浮层都会和内容抢位置 |
| `result` 结算 | 视觉中心 = 星级 + 角色表情；四格数据（得分/答对/正确率/连击）压成一行小字；按钮最多 2 个（主 + 次） |
| `avatar` 皮肤 | 大立绘陈列 + 名称 + 解锁条件；未解锁整体置灰（已有实现，只需 token 化与尺寸规范） |

## 五、设计系统（token 化）

### 5.1 现状实测（这是全部问题的技术根因）

| 指标 | 实测值 |
| --- | --- |
| `var(--*)` 使用次数 | **0**（`app.wxss` 定义了 11 个变量，全项目一次没用） |
| 硬编码色值出现次数 | **1613**（页面文件里 1547） |
| 不同色值个数 | **330** |
| 白色 | `#fff` 216 次 + `#ffffff` 78 次 |
| 「深色文字」竟有 6 种 | `#3a3a5c`(101) `#2c4a6b`(26) `#2f5470`(21) `#333a45`(11) `#4a6b8a`(10) `#3b3b5f`(9) |
| 「次要文字灰」有 5 种 | `#5c7f9e`(91) `#8a9bb5`(89) `#8a94a6`(14) `#7b93ad`(12) `#93a9bd`(11) |
| 蓝色系 | 至少 11 种（`#4cc9f0` `#4285f4` `#2e6fd6` `#6aa6f5` `#4a90d9` `#8fd0ff` `#c9ecff` `#eaf8ff` `#7ec8ff` …） |
| 橙色 | `#ffb703`(87) + `#ff8f00`(19) + `#ffd166`(16) |
| 近似的浅灰底 | `#eef2f8`(16) `#eef3fa`(12) `#eef5fb`(8) —— 肉眼几乎分不出的三种 |

| 字号 | 38 种取值（20/22/24/26/28/30… 以 2rpx 为步长，共 19 档小字号） |

### 5.2 颜色 token（330 → 24）

**迁移友好**：token 值**直接采用现有高频色**，而不是发明新色 —— 这样 60% 的替换是「等价替换」，视觉不会突变。

| token | 值 | 吸收的现有色 | 用途 |
| --- | --- | --- | --- |
| `--c-sky` | `#5aa9e6` | 主色 | 页面背景主色（与 `app.json` navigationBar 一致） |
| `--c-sky-2` | `#d8efff` | | 背景渐变下沿 |
| `--c-surface` | `#ffffff` | `#fff`(216) `#ffffff`(78) | 卡片/面板底 |
| `--c-surface-2` | `#eef2f8` | `#eef3fa` `#eef5fb` | 次级底/分组底 |
| `--c-ink` | `#3a3a5c` | `#3b3b5f` `#333a45` | 主文字 |
| `--c-ink-deep` | `#2c4a6b` | `#2f5470` `#4a6b8a` | 浅色背景上的正文 |
| `--c-text-sub` | `#5c7f9e` | `#7b93ad` `#93a9bd` | 次要文字 |
| `--c-text-mute` | `#8a9bb5` | `#8a94a6` | 弱化文字/占位 |
| `--c-primary` | `#ffb703` | | 主按钮（橙） |
| `--c-primary-deep` | `#ff8f00` | | 主按钮按下态 |
| `--c-accent` | `#4cc9f0` | `#8fd0ff` `#c9ecff` `#eaf8ff` `#7ec8ff` | 次按钮/高亮（青） |
| `--c-blue` | `#4285f4` | `#2e6fd6` `#6aa6f5` `#4a90d9` | 链接/选中态 ⚠️ 见 5.5 冲突项 |
| `--c-success` | `#7bd389` | `#2fa96b` | 成功/正确 |
| `--c-success-ink` | `#2e8b57` | `#34a853` | 绿文字 |
| `--c-danger` | `#ff5a5a` | `#e62e2e` | 错误/危险 |
| `--c-pink` | `#ff5d8f` | | 强调粉 |
| `--c-gold` | `#ffd166` | | 星/成就 |
| `--c-line` | `rgba(58,58,92,.10)` | 各页自定的边框 | 分割线/描边 |
| `--c-shadow` | `rgba(0,0,0,.10)` | | 阴影基色 |
| `--c-mask` | `rgba(0,0,0,.45)` | | 遮罩 |

> 覆盖度：前 18 个现有色值占全部着色点的 **57.2%**，加上上表合并的近似色，token 化可覆盖约 **65%**；
> 剩余 35% 是长尾一次性色值（如各玩法的专属配色），**按就近映射**处理，不追求 100%。
> ⚠️ 玩法内页的功能色（如贪吃蛇的应拼字母绿/干扰红、数独的宫格色）**允许保留独立色**，
> 但必须登记在 `app.wxss` 的「玩法专用色」注释区，避免再变成无主色值。

### 5.3 字号阶梯（38 → 8 档）

现有高频值是 22/24/26/28/30（2rpx 步长）。为**降低迁移风险**，阶梯保留 2rpx 粒度但限定档数：

| token | 值 | 现有频次 | 语义 |
| --- | --- | --- | --- |
| `--fs-cap` | 20rpx | 47 | 角标/最小说明 |
| `--fs-sm` | 22rpx | 131 | 卡片副标题 |
| `--fs-sm2` | 24rpx | 97 | 次要正文 |
| `--fs-md` | 26rpx | 85 | 正文 |
| `--fs-md2` | 28rpx | 67 | 正文强调 |
| `--fs-lg` | 32rpx | 41 | 小标题 |
| `--fs-xl` | 40rpx | 45 | 页面标题 |
| `--fs-hero` | 48rpx | 12 | Hero/大数字 |

> 超出 8 档的（30/34/36/38/44/52/72/110/200…）按语义就近归并；`200rpx`、`180rpx` 这类是游戏内特大数字，归入 `--fs-display`（允许玩法页例外并登记）。

### 5.4 圆角 / 间距 / 阴影

```text
圆角：--r-sm 8rpx ｜ --r-md 16rpx ｜ --r-lg 24rpx ｜ --r-xl 32rpx ｜ --r-pill 999rpx ｜ --r-circle 50%
间距：--sp-1 4rpx ｜ --sp-2 8rpx ｜ --sp-3 12rpx ｜ --sp-4 16rpx
      --sp-5 20rpx ｜ --sp-6 24rpx ｜ --sp-7 32rpx ｜ --sp-8 40rpx
阴影：--sh-1（卡片）｜ --sh-2（浮层）｜ --sh-hard（卡通硬阴影：0 8rpx 0 rgba(0,0,0,.10)）
```

现有圆角 27 种 → 6 档；间距（4~40rpx 的 16 种高频值）→ 8 档。

### 5.5 ⚠️ 需要你拍板的一个冲突项

**tabBar 选中色 `#4285f4`（`app.json`）与设计主色 `#5aa9e6` 是两套蓝。**

- 豆包设计稿的 tab 高亮是**橙色**（跟主按钮同色系）；
- 现在是蓝色 `#4285f4`，且与页面天空蓝 `#5aa9e6` 不同源，并在 26 处被引用。

**建议**：tab 选中色改为 `--c-primary`（橙）或 `--c-sky`（与页面同源）。这属视觉决策，**必须你定**（见 §8）。

### 5.6 组件库（`app.wxss` 统一提供，页面只引用）

已有基础（可复用扩展）：`.btn` + 3 尺寸（`-lg/-md/-sm`）+ 5 语义色、`.card`、`.tag/.badge`、`.empty-state`、`.progress-bar`、`.btn-back`。

**需补齐**：
- `.card--hero`（首页 Hero 容器）
- `.block`（一屏一块的标准间距容器，替代各页自己写 margin）
- `.chip`（次级入口小胶囊，§4.2 的 ⑥ 用）
- `.stat-row`（结算四格数据一行，替代各页自写）
- `.list-row`（排行榜/错题本/每日一题共用的「图标 + 标题 + 副标题 + 箭头」行 —— 现在各页都自己写了一遍）

**已存在的可复用组件**（`miniprogram/components/`）：`game-hud`、`settle-pop`、`warrior-badge`。本轮把主干页也接上，避免重复实现。

## 六、素材规格（把「效果图」变成「能用」）

| 包内默认怪兽 `monster_01.png` | 同上 | 340×197 |
