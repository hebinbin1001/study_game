## 一、界面体检（实机截图，非手绘）

用微信开发者工具的自动化截图接口实拍了 6 个关键页面，图在 `e2e/reports/`：

| 文件 | 页面 |
|---|---|
| `01-home.png` | 首页 |
| `02-playlist.png` | 玩法 tab |
| `03-level.png` | 关卡页（蛇形地图） |
| `04-mode-pick.png` | 进关前的形态选择层 |
| `05-study.png` | 学习 tab |
| `06-me.png` | 我的 |
| `07-game-running.png` | 对局进行中 |

整体观感：卡通低饱和、卡片圆角与配色统一，学习 tab 与我的页信息层级清楚，**没有渲染错位或溢出**。以下是值得处理的问题。

### 1.1 同一项数据在两个页面显示成两个数字（建议优先修）

| 位置 | 字段 | 实测 | 数据来源 |
|---|---|---|---|
| 首页 资产条「累计星星」 | `totalStars` | **5** | 本地存档 `storage.getAllStars()` 累加（按 学段@题型@关卡 取历史最大值） |
| 我的 统计格「累计星星」 | `rankStars` | **87** | 云端 `/api/rank/info` 的 `stars`（`rank_records.stars`，由 `/api/rank/sync` 每局累加） |

两个口径完全不同（本机进度 vs 云端累计），却共用一个名字。玩家会以为数据出错。
**建议**：要么统一取云端（登录后），要么明确区分文案——本机显示「本机进度 ★5」、云端显示「累计获得 ★87」。

### 1.2 对局画面可能整屏空白（健壮性）

`07-game-running.png` 里：HUD（5 颗心 / 得分 0 / 第 1/10 题）和四个选项都正常，**但画布上既没有怪兽也没有题目**，整片天空色。

根因：引擎只在 `requestAnimationFrame` 回调里执行 `render()` —— 渲染循环一旦被节流或停摆，**一帧都不会画**。
（开发者工具窗口不在前台时 rAF 会被节流，这是同一根因；真机通常不触发，但首帧要等一次 rAF 才出画是客观事实。）

**建议**：`engine.start()` 之后同步补一次 `render()`，让首屏立刻可见。改动极小，收益是"进关即见题"，而不是空白半秒。

### 1.3 其余观感问题（都是小改）

- 学段 tab 与分类 chips 右侧被裁切（如"小学5-6""数学"），没有"还能横滑"的视觉暗示 → 建议加右侧渐隐或让末项半露。
- 锁定节点内"通关上一关解锁"字号小且在圆内折行，远看糊成一团。
- emoji 图标风格不统一：有的渲染成彩色 emoji、有的成单色字形（我的页段位图标甚至呈方块字形）。建议关键位置换成矢量/图片资源或统一用同一套 emoji。

## 二、现在"关卡 + 形态"为什么和玩法脱节

现状链路：

```
首页「继续挑战」┐
                ├─→ 关卡页（标题：选择关卡｜学段 tab + 题型 chips + 进度卡 + 蛇形地图）
玩法 tab「字母射击」┘        │
                            └─→ 点节点 → 对局页 → 【形态选择弹层】→ 开始
玩法 tab 其余 7 款 → 各自独立页面（数独/2048/24点/连连看/贪吃蛇/消消乐，各有一套自己的关卡或直接开打）
```

四个具体症状：

1. **关卡页没有"玩法身份"**。标题是通用的"选择关卡"，从首页进来和从玩法 tab 进来看到的是同一页，看不出这属于"字母射击"这个玩法。
2. **形态是"每关必弹的模态"**，且只有"第 1 关"三个字的信息量。它本质是难度/节奏设置，却被做成了每局都要点一次的过场。
3. **首页「继续挑战」不是"继续"**。副标题写着"选择学段·题型·开始闯关"——那是关卡页的说明书，不是进度；点进去还得再选一遍。
4. **玩法卡只有"已解锁"**，没有"我打到哪了"。8 款玩法的进度散落各处，玩法 tab 上看不到。

## 三、改版设计

### 3.1 总体：把结构理顺成三层

```
玩法（第一层）  →  关卡（第二层，属于某个玩法）  →  形态（第三层，是玩法的模式/难度档）
```

一句话：**玩法是身份，关卡是进度，形态是设置。**
- 玩法决定了"我玩的是什么"（题库来源、对局规则）；
- 关卡是玩法内部的进度，不同玩法可以有不同的关卡体系（字词=学段+题型+10 关；数独=20 关；2048=7 关…）；
- 形态不再是每关都要过的弹层，而是**玩法内部的一个持久设置**（仅字母射击有）。

### 3.2 玩法卡 = 进度入口（玩法 tab）

```
┌───────────────────┐
│ 🔫  字母射击        │
│ 挖空补词 · 打跑怪兽  │
│ ▓▓▓░░░░░░  3/10 关 │  ← 新增：进度条 + 已通关数
│ ★6 · 幼儿园        │  ← 新增：总星 + 当前学段
│      [继续 ▶]      │  ← 新增：主按钮，直接开下一关
└───────────────────┘
```

- 点卡片主体 → 该玩法的**关卡页**；点「继续」→ **直接进下一关**对局。
- 未解锁玩法（弹弹球）保持现状。

### 3.3 关卡页 = 玩法关卡页（含模式栏）

```
┌────────────────────────────────┐
│ ←   🔫 字母射击          ⭐ 6/30 │  ← 玩法头部（图标+名称+总星），替换现在的"选择关卡"
├────────────────────────────────┤
│ 模式： [经典]  Boss  极速        │  ← 形态内联成一行 chips（仅字母射击显示）
├────────────────────────────────┤
│ 学段： [幼儿园] 小学1-2 小学3-4 … │  ← 字词类玩法才显示
│ 题型： [综合] 单词 词语 成语 …    │
├────────────────────────────────┤
│                                │
│        蛇形关卡地图              │  ← 节点增加玩法语义（见 3.6）
│                                │
├────────────────────────────────┤
│ + 自定义关卡                    │
└────────────────────────────────┘
```

- 头部由"选择关卡"改为**玩法名 + 该玩法总星进度**，解决"看不出这是哪个玩法"。
- 学段/题型两栏**只对字词类玩法显示**；数学类玩法（数独/2048/24点）显示"关卡 1–20"之类的纯进度筛选。
- 自定义关卡入口保留（它属于字词玩法）。

### 3.4 形态：从"每关弹层"改为"玩法模式栏"

形态的三种（经典 / Boss 狂潮 / 极速竞技）本质是**难度与节奏档**，落在关卡页顶部作为一排 chips：

- 点选即切换，**记忆上次选择**（已有 `ww_mode` 存储，直接复用）；
- 点关卡节点**直接开局**，不再弹层；
- 好处：每关少一次点击；模式成为稳定设置而不是过场；关卡与模式在同一屏完成选择。

> 备选做法 B：保留弹层，但补齐上下文（玩法名 + 学段/题型 + 关卡号 + 该关历史最佳星 + 三个模式各自"本关会怎样"）。做法 B 改得少，但每关仍多一次点击。

### 3.5 首页「继续挑战」= 真·继续

```
┌────────────────────────────────────┐
│ ⚔️  继续挑战                  ★★☆  │
│    字母射击 · 幼儿园 · 第 2 关       │  ← 具体进度，而不是操作说明
│                          换关卡 ›   │  ← 次入口：进玩法关卡页
└────────────────────────────────────┘
```

- 主点击 → **直接进该关对局**；
- 右上角"换关卡" → 玩法关卡页（想换学段/题型/模式时走这里）。

### 3.6 关卡节点增加玩法语义

- 字词类：节点在主数字下方加**该关主题小字**（如"成语""单词"）——现在的徽标只在非"综合"时出现，且压在角上。
- 数学类：节点显示目标（如 2048 的"目标 512"、24 点的"第 N 关"）。
- 已通关节点保留 ✔ + 星数（现有设计不错）。

| # | 选择 | 我的建议 |
