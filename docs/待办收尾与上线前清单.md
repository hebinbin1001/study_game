### 5. 仍需拍板的两条口径（**没做，等你定**）

**① 星级进度登录后云同步（M5 T4.2）—— 建议先不做。**

原因（口径冲突，硬做会出问题）：本地 `ww_stars` 是「**每关历史最高星**」的集合，
云端 `rank_record.stars` 是「**每次通关累加**」的流水；两者语义不同。
把本地总和直接覆盖上去，段位会跳变或回退（老玩家的段位被"快照"打折），
而求和又会重复计算（同一关反复通关云端早就累加过）。

可执行的替代：改成「**按学段取本地与云端较大值**」—— 需要新接口 `POST /api/stars/merge`
（body 传本机汇总，服务端不做覆盖而做 max）+ 可能给 `rank_record` 加一列存快照来源；
或者干脆维持现状（游客成绩登录后才入榜，本机进度只影响本机关卡解锁）。
**要哪种，你说一声。**

**② 青少年模式 / 防沉迷（实数时长限制、实名认证）—— 属合规范围决策。**

现状：隐私协议弹窗、完整协议文本页、未成年人条款已落地（`pages/agreement/`）。
未做：青少年模式时长限制、防沉迷实名认证 + 时段限制。

M4 spec 里列了这三项，但这是**教育类小程序**（非游戏类目、无版号），
平台并不强制实名防沉迷；真要做，需要接实名认证服务（成本 + 隐私政策同步改），
收益主要是「未成年人保护姿态」。**要不要做、做到哪一档，等你定。**
