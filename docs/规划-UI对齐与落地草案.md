## 二、UI 落地规划（严格按 demo/ui-demo.html）

### 2.1 新建 4 Tab（app.json tabBar）
- 页面：首页 index、玩法 playList、学习 study、我的 mine（新页面或改造现有页）
- tabBar icon：需 81×81 PNG（选中/未选中两态），emoji 不行 → 需做 4 组图标
- 现有页归属：形象/成就/排行/报告/错题/设置/注销 从各自 tab 内进入（保持 navigateTo）

### 2.2 首页 = demo home
1. Header：⚔️词力战士 + 🔊声音开关（无段位胶囊——已按用户去掉）
2. Hero 头图：圆形角色头像 + 标题 + 副标题（登录/游客两态头像）
3. 游客引导条（仅游客）：游客模式·数据仅存本机 + 去登录
4. 资产条：⭐累计星 / 🎖段位 / 🔥连续（游客=0/游客/0天）
5. 排行榜行：我的第 N 名 → rank
6. 今日目标/学习进度卡（已答/正确率/达标进度）
7. 每日一题卡（=签到，整卡点击）
8. 继续挑战大卡（当前关卡进度→level）
9. 推荐玩法 2 卡（字母射击→game；数独/消消乐→按解锁）

### 2.3 玩法 tab = demo playList
- 信息条（N 款玩法 · 已解锁 X）+ 分类筛选 chips（全部/射击/配对/连线/反应/数学）
- 2 列玩法卡（图标+名称+描述+状态标签 已解锁/未解锁 + 数学角标）
- 可点玩法：字母射击(已实现→game)、数独(demo可玩，真实页待做)；其余未解锁(灰置/敬请期待)
- 每玩法一个独立闯关线（关卡固定：数学类固定关卡；字词类题库出题）——见十六节

### 2.4 学习 tab = demo study
- 本周学习概览卡（学习天数/星星/正确率/连续）
- 学习报告 → pages/report（改造）
- 错题本 → pages/wrong-book（改造）
- **每日一题·签到**（与首页同一条：完成即签）
- **自定义题库** → 「我的题库列表」（新建草稿/审核中/已公开/他人公开大厅）
- **签到日历页**（原 checkin 改造为只读记录+里程碑日历，入口在学习 tab 每日一题旁；不可直接打卡）

### 2.5 我的 tab = demo mine
- 顶部资料卡：头像 + 昵称 + 段位行 + 「📝编辑 / 🔑登录」
  - 游客点 → 登录；登录点 → 编辑弹窗（昵称/头像/段位展示）
- 游客说明卡（仅游客）
- 统计三格（⭐/🎖/🔥；游客 `-`）
- 菜单：排行榜 / 形象皮肤 / 设置（声音/协议/清缓存）→ 对应真实页
- 危险区（仅登录）：退出登录 / 注销账号（双确认）

### 2.6 排行榜页（双榜，真实数据）
- 顶部 r-tab：⭐总榜·星星 / 🎮按玩法·进度
- 玩法 chips（全部/数独/2048/24点/字词…按 game_type）
- 榜单行：名次(前3金)+头像+昵称+指标(总榜=⭐数 / 玩法榜=进度+星)+我的高亮
- 底部我的名次卡：游客 → 🔒登录后可上榜

### 2.7 设计 token 对齐（不推翻现有视觉）
主色 #4285F4 / 成功 #34A853 / 错误 #EA4335 / 奖励 #FF9800；卡片大圆角 24rpx+、胶囊控件、8 倍数间距。逐步收敛 app.wxss（已存在 13 节 token 基线，跳过推翻重来）。

## 三、功能改造清单（后端 + 前端，按模块）

### M-A：4 Tab 信息架构重构
- app.json：tabBar + 页面调整（index 重做、新增/改造 playList/study/mine 视图）
- 首页去宫格化：登录条/统计卡/开始闯关改造为 demo home 结构；原宫格入口改 tab 内菜单
- 新/改页面：pages/playlist、pages/study（或 index 内分 view）；me 对齐 demo
- 涉及:app.json、app.wxss、pages/index、pages/me、（新）pages/playlist/study、tab 图标资源

### M-B：每日一题 = 签到（双轨，后端 + 前端）
- 现状：checkin 手动 + auto（任意闯关自动打卡）；服务端奖励写死 1/3/7/14/30 天送星累加 RankRecord.stars
- 改造：
  1. 每日一题：每人每天 1 题（按学段+题型随机，服务端按 openid+date 幂等下发/判定）
  2. 完成每日一题 → 当日签到（轨道 A：调用 doCheckin 日历星奖励，旧数值保留）
  3. 轨道 B：每日一题连续里程碑 7/15/30/60/100/250/365 → 星星/限定皮肤（需里程碑计数与奖励表；皮肤与现有 avatar 解锁体系衔接）
  4. 首页 + 学习 tab 每日一题入口 → **轻量单题页**（题干+选项+完成即签+连续天数+里程碑进度）→ 签到成功提示
  5. 原 checkin 页改造为**只读「签到记录 + 里程碑日历」**（不可打卡）
  6. **移除 checkin/auto**：result 通关不再自动打卡；打卡唯一入口 = 每日一题完成
  7. 轨道 B 里程碑（7/15 星、30/60/100/250/365 皮肤）在服务端记录每日一题连续天数（断签归零）并发放；皮肤走 avatars `unlockType='milestone'`

### M-C：排行榜双榜（后端）
- 现状：rank_records(openid/rankId/wins/stars) 单榜；无 game_type
- 改造：
  1. **总榜=星星**：沿用 RankRecord.stars（通关星+签到星+里程碑星累加）——即现状口径作为总榜
  2. **玩法进度榜**：scores 加 `game_type`（默认 word_warrior 兼容现有关卡）+ 每玩法最大关卡进度聚合
  3. **字词榜再细分**：玩法榜 word 支持 学段 tab + 题型 chips（进度=该学段@题型已通关最大关卡）；服务端按 grade@type 聚合
  4. 接口：rank/total（前N+我的）、rank/progress?game=type[&grade=&type=]（玩法榜前N+我的）
  5. 前端 rank 页按 demo 双榜 UI 接真实接口；游客只读公开榜
- 数据说明：字词闯关=word_warrior（grade@type@level 进度服务端化），数独=sudoku（后续）等

### M-D：自定义关卡对齐「10 个一组」（后端 + 前端）
- 现状：level-editor 手工逐题 {type,q,a,hint} 不限数；server totalQ=len；**game 不消费 customLevel → 自建关不可玩**；无大厅
- 改造：
  1. 服务端强校验：提交审核时 totalQ===10 才可 submit（create/saveDraft 可少于10）
  2. 前端：模板式录入/批量文本导入（接线 parser.js/validator.js——词库格式规范见 docs/词库格式规范.md，10 行一组）；10 题进度条
  3. **打通游玩**：game.js 消费 customLevel 参数加载 items 出题（把 8 码题型映射进现有引擎或复用错题复习三形态思路）
  4. 学习 tab「自定义题库」入口 → 我的关卡列表（草稿/待审/已公开）+ 公开关卡大厅（approved 全量可玩）
  5. 审核管理：保留 API +（可选）管理页面

### M-E：游客 = 现状保留（前端，验证/补强）
- 前 3 关默认开放、游客本地星（ww_stars）已实现；确认不建档、数据本机
- 补充：游客完成第 3 关 / 点击第 4 关时登录引导（demo 引导条一致）；受限入口引导保留
- 确认游客本地成绩在后端无任何记录（无 openid 不上报）——现状 score/wrong/checkin/rank 均已按登录过滤

### M-F：数独玩法真实化（可后置）
- demo 已有 4×4 玩法样例；真实页 = 独立玩法页 + game_type=sudoku + 固定关卡（4×4→6×6→9×9 提示数递减，见十六节）
- 需要：公共对局外壳抽取（12 节）后接入（HUD/结算/上报/错题），或独立轻量页先跑

### M-G：公共对局外壳抽取（架构预备，12节已有）
- HUD（❤/得分/连击/暂停/计时）+ 结算 + 错题/成绩上报 + 声音开关 + 暂停遮罩 抽公共模块 → 新玩法（数独/2048/24点/消消乐）复用
