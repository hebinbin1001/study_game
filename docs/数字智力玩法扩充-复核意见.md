### 1.1 找规律 —— 做，三处必须改

原文的三个理由（零素材 / 无限出题 / 正确率折星）都成立，并且**与现有内容零撞车**：全仓 grep `找规律|数列` 在 `miniprogram/game`、`utils`、`data` 里 **0 命中**，题库里没有任何数列题。

要改的三处（外加 1 条可选）：

- **关卡表必须封顶（最重要）**。原文写「不设上限（照 g2048 先例）」，但 g2048 的 `totalOf=0` 指的是**不计入"共 N 关"**，它的关卡表仍是 14 条写死的故事线。而 `storage.saveStars` 的星星会被首页 `getAllStars()` 求和 → 直接进段位/皮肤门槛。**无限关卡 = 无限刷星**，会立刻冲穿刚审计过的「单学段天花板 150 星 vs 皮肤门槛最高 620 星」这条线。
  → 建议：**30 关 / 每关 10 题**，题面程序生成（重玩换题），星星只记最高。30×3 = 90 星，与华容道同级。
- **题型族按关卡序号递进，不按年级 gate**（用户 2026-10-18 口径：数字智力和年级关系不大）。同一关对所有人生成同一题型，难度曲线靠"打到第几关"自然形成，详见 §2.2。
  → 建议 30 关五档：**1~6 关** 图形/符号规律 + 等差(+1~+5)；**7~12 关** 等差（含递减）+ 交替(+a,+b)；**13~18 关** ×2 等比 + 平方数；**19~24 关** 二阶等差；**25~30 关** 斐波那契式 + 挖 2 空（全部放开、混合出题）。
- **加「图形规律」题型族**，别只做数列。`▲▲●▲▲●?` 这类用 emoji 就能排，0 素材、0 读数负担，放在最低几关当入门最合适——**不需要靠年级判断谁该看图形题，第 1 关就是它**。
- 差异化（可选但值）：只做「4 选 1」在操作层与「限时抢答」同构。加一条"作答后显示规则解释"（"每次 +3"）成本很低，却是它相对其他玩法的唯一护城河；呈现用串珠/数轴横排，缺项留空格，答案从下方数字块点入。

### 1.2 时钟 / 时间推理 —— 提到第 2

- **生活必需技能，跟年级无关**：认表、算经过时间不属于任何一册教材的"进度"，是迟早要用上的常识。在这个 6~12 岁产品里，"家长觉得有用"比"玩法深度高"更能决定留存与付费；原文把它排第 5，是拿"玩法新鲜感"而不是"家长决策逻辑"在排。
- **难度同样按关卡序号递进**（不接年级）：1~6 关整点/半点，7~12 关 5 分刻度，13~18 关 1 分刻度，19~24 关经过时间（分内不进位），25~30 关跨小时/24 时制/时间比较。表盘刻度与指针精度本身就是一条干净的难度阶梯，不需要问用户几年级。
- **素材成本≈0，且原文高估了 UI 成本**：表盘 = 一个圆 + 两根 `transform: rotate()` 指针 + `conic-gradient` 刻度环，纯 CSS，不用图，也不用 canvas。
- **真实成本在题型**：认读（给表盘选时刻）→ 经过时间（9:20 再过 40 分钟）→ 时间比较 → 24 时制。**"拨钟"要拖拽，交互成本高于选择题，放 P2**；P1 只做认读 + 经过时间（点选/选择）。
- 与现有 8 款完全不撞：全仓无任何钟表/时间题（`rel-time.js` 是"3 分钟前"这类相对时间文案，与本玩法无关）。

### 1.3 算术迷宫 —— 降一档，先解决"没有选择"

原文说「DFS 回溯生成保证必有解 → 可测」是对的，但**DFS 回溯（recursive backtracker）生成的是完美迷宫：任意两格之间路径唯一**。也就是说玩家没有路线选择，实质是"沿唯一路径连续答口算题"——空间规划维度≈0，剩下的就是口算，而这正是「口算冲刺」已覆盖的能力。

要让它真的是迷宫，至少做一条（按性价比排序）：
1. **支路宝箱**（推荐）：主路径之外造支路，支路尽头答对得额外星星或"跳一题"，让"走哪条"有意义；
2. **braid 化**：生成后按 20~30% 概率拆掉死胡同的墙形成回路，玩家能绕路；
3. 门分难度、答错锁格 5 秒（不回退，降低挫败感）。

另外两处被低估的成本：
- **门塞不进格子**。6×6 时每格约 55rpx 宽，`12+7` 放不下 → 门必须是"进格后弹浮层算式"，格子上只显示 ✓/✗/锁。这是"格子 + 浮层"两套 UI，不是纯 CSS 网格。
- **星级口径与既有拍板冲突**。原文写「按通关用时或错误次数折三档」，但 2026-10-17 已拍板"3 星统一按正确率"，`challenge.js` 里 `starsByLives` 已标 deprecated 并注明"新玩法请用 `starsByRightRate`"。迷宫**有题目**，就该用 `starsByRightRate`（三档可达天然成立），不要自己发明用时口径。

### 1.4 汉诺塔 —— 降到最后，且 4 柱方案技术上不成立

- 原文的 `minMoves = 2ⁿ − 1` **只在 3 柱成立**。4 柱（Reve's puzzle）没有闭式解，Frame–Stewart 至今仍是猜想最优 → 原文「3 柱/4 柱两种变体 + 闭式解单测」自相矛盾。
- 若真要 4 柱：n ≤ 8 的状态空间 4⁸ = 65 536，**构建期 BFS 一次算准**最优步数并落成表（单测钉表），不要写 `2ⁿ−1`。
- 产品判断同原文：最优解唯一、学会递归后每关同一套动作、家长看不出教学价值。**建议只做 6 关小品**（3~8 盘，3 柱），或者直接不做。

### 1.5 数字推盘 —— 不做

- 与华容道同为"滑块到目标位"，原文自己也承认。
- 它唯一的可测优势是"可解性有判据 + 最优步数可算"（3×3 奇数宽：**逆序数为偶**即可从标准态达成；4×4 这类偶数宽才需要再加"空格所在行"判据）。但**这个优势在这个项目里已经不新鲜**：华容道关卡表里本来就带 `minMoves`，结算显示"用了 X 步（最少 Y 步）"，`starsFor` 也是按步数倍率折星（`klotski.js:384`）。也就是说"最少步数挑战"华容道已经在做了。
- 结论：**不做**。若哪天确实想要 3×3 滑块，正确做法是给华容道加一档图案小的关卡，而不是新开一个玩法（省掉 13 处接入 + 一整套页面）。

## 二、硬约束（2 条）+ 一处自我更正

### 2.1 星 economy：关卡表必须有限

`storage.saveStars(mode, no, stars)` 的星星会被首页 `getAllStars()` 汇总成"累计星星"，段位阶梯（`rank-ladder.progressOf`）与皮肤解锁（60~620 星）都按它推导。
→ 任何"无限关卡"的新玩法都必须**先封顶**（建议 30 关 × 3 星 = 90 星）。"无限出题"只能体现在**关内换题**，不能体现在**无限关卡**。

### 2.2 难度阶梯靠关卡序号，不接年级

本文初版主张"题型族按学段 gate"，这条**是错的**，按用户 2026-10-18 的口径改正：数字智力是益智板块，和年级关系不大。三条实证理由：

1. **与现有实现一致**。实测 `sudoku / math24 / klotski / onestroke / memory-grid / tw2048 / g2048` 的引擎里 `grade` **零引用**，关卡表是静态的、与年级无关。只有 `math-sprint / balance` 按 `gradeScale` 出题——那是**学科口算**（`puzzle-levels.js` 里一关对应一个年级，`totalOf = GRADES.length`），和数字智力不是一类东西。
2. **存档与榜单口径已经是"无年级"**。数字玩法的星星写的是 `saveStars('onestroke', 关号, 星)` → 实际 key 是 `onestroke_7`，**没有年级维度**；上报是 `reportPlay({ gameType:'onestroke', grade:'all', level:关号 })`。若同一关按年级出不同题，同一个 `level` 就对应了不同难度，进度榜分数不可比、星级也不可比。
3. **关卡本身就是闸门**。第 1 关永远不含斐波那契，第 25 关的玩家已经过了 24 道门槛——这层筛选比"系统按年级分配"更贴合实际能力。低龄玩家想玩就在前几关玩，高年级玩家也能从第 1 关复健，不需要系统替他判断。

→ 规格上把"学段 gate"整节替换成**一张 `tierOf(level)` 题型上限表**（见 §四），实现比 `gradeScale` 更简单，单测也更好钉：断言"第 n 关生成的题型 ∈ 该档允许集合"。

### 2.3 迷宫类必须"有岔路"

程序生成的**完美迷宫**没有选择，等于给口算题套了一层格子皮。不做 braid 或支路，这个玩法就不该叫"迷宫"。
