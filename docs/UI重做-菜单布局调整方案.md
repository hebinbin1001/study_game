# 菜单布局调整方案（玩法 / 学习 / 我的）

> 审计时间 2026-10-17。只谈**布局与信息架构**，配色主题统一（天空底 + 白卡 + 橙 CTA）放到收口批次。
> 线框对比见 `demo/ui-redesign/menu-layout-plan.html`。

## 一、审计结论（带数字）

### 1. 玩法 Tab：4 层筛选把首屏吃掉 1/3

`playlist.wxml` 从上到下依次是：蓝色信息条（114rpx）→ 年级 chips（~72rpx）→ 二级分段（~108rpx）→ 分类 chips（~86rpx），
合计约 **380rpx** 才出现第一张卡片；1334rpx 屏上首屏只能看到 2 行半（5 张卡 / 7 张）。

三个具体问题：
1. **信息条价值低**：「15 款玩法 · 已解锁 14」和分段里的内容重复，却占 114rpx。
2. **绿框语义错位**：`playlist.wxml` 用 `class="pcard {{item.unlocked ? 'done' : 'new'}}"`，
   `playlist.wxss` 的 `.pcard.done { outline: 4rpx solid #34A853 }` —— 结果是 **14 张已解锁卡全被绿框包住**，
   绿色不再表示"已完成"，只是"能玩"。
3. **未解锁卡占网格位**：`bounce`（单词弹弹球）`unlocked:false`，占掉一格并把内容推多一行。

### 2. 关卡页：头部 540rpx，列表只剩 4 行

`level.wxml` 头部有 5 块：标题两行、学段 tabs、题型 chips、星星进度卡、里程碑宝箱行，约 **540rpx**；
1334rpx 屏上列表只剩 ~740rpx（4 行），而主线有 30 关。

三个具体问题：
1. **题型 chips 与「挑战主线」混排**：主线 + 8 个题型（带数量角标）在同一条横滑里，用户分不清"主线"和"自由练"。
2. **没有「回到当前关」**：30 关竖排，从第 1 关滑到第 20 关要滑很久；没有置顶的"继续"入口。
3. **Boss 关没有主题化**：第 30 关只多一枚「BOSS」小字标签，和首页做好的 Boss 预告/立绘完全不呼应。

### 3. 学习页：6 条同权重长条 + 底部约 350rpx 空白

`study.wxml` 是「本周卡 + 6 条 `.link` 行」，每条同字号同权重（报告/错题本/每日一题/签到/题库/自建关卡），
没有主次；1334rpx 屏上底部留白约 **350rpx**，且"学习报告""错题本"这两个真正有数据价值的入口被压成普通行。

### 4. 我的页：9 条菜单平铺无分组

`me.js` 的 `menu` 9 条：形象皮肤 / 排行榜 / 每日挑战 / 赛季 / 好友 PK / 错题本 / 教材版本 / 成就 / 协议。
其中 **排行榜、每日挑战、赛季、好友 PK、错题本** 在首页/学习页已有入口（保留，不删），但平铺在一起没有分组；
「用户协议」这种低频项占一整行 108rpx。

### 5. 数字智力关卡页反而是好样板

`puzzle-level` 是「头部信息条 + 提示 + 滚动列表 + 底部返回」，头部只有 ~180rpx，列表占满剩余高度 ——
说明问题不在"关卡页"这个形态，而在 `level` 页堆了太多筛选控件。

## 二、方案（三档，可分批做）

### P0 修正（bug 级，不动结构，约 0.5 天）

| 改动 | 文件 | 收益 |
|---|---|---|
| 绿框只在「该玩法线 30 关全通」时出现，已解锁不描边 | `playlist.wxml` / `.wxss` | 去掉 14 张卡的噪音边框 |
| 未解锁玩法移出网格，改页脚一行「🏐 单词弹弹球 · 制作中」 | `playlist.wxml` | 网格 15→14 格，少一行 |
| 卡片底部「已通关 x/30」+「去闯关」合成一枚胶囊 | `playlist.wxml` / `.wxss` | 少一个标签层 |

> 这三条是明显缺陷，不涉及方向选择，确认后可直接改 + 跑静态护栏。

### P1 布局收敛（需要你拍板，约 1.5~2 天）

**玩法页：4 层 → 2 层，头部 380 → 236rpx**
- 删蓝色信息条，「已解锁 14/15」并进年级行右侧；
- 年级 chips、分段、分类保持，但分类只显示当前分段有的类（已经是这样）；
- 首屏可见卡片 4 → 6 张。

**关卡页：头部 540 → 320rpx，加"继续当前关"**
- 去掉标题两行（导航栏已有页面名）；
- 宝箱行并进进度卡（`⭐ 42/90　📦10关·已领　📦20关`）；
- 题型 chips 收进二级分段「🎯 挑战主线 / 🎲 自由练」，默认主线（自由练里再按题型筛）；
- 头部下方固定「⚔️ 继续第 N 关 · 玩法名」，点击直达；
- 列表每 5 关加分段标题，进入页面自动滚到当前关；
- 第 30 关 Boss 换暗紫卡 + Boss 立绘（复用 `utils/boss-ladder.js`）。

**学习页：2 张数据卡 + 4 行 + 薄弱题型**
- 「学习报告」「错题本」升级成并排数据卡（正确率 / 待复习数，数据来自 `/api/report/range`、错题本接口）；
- 其余 4 条保持行样式，行高 108 → 96rpx；
- 底部补「🎯 本周薄弱题型 Top3」填满剩余高度（数据已有，`report` 的薄弱题型聚合）。

**我的页：菜单分 3 组 + 2 条小字**
- 成长（形象皮肤 / 成就勋章 / 排行榜）· 对战（每日挑战 / 赛季 / 好友 PK）· 学习（错题本 / 教材版本）；
- 「用户协议」移到版本号旁做小字链接；危险区不动；
- 重复入口**全部保留**（兼容要求），只归位 + 加分组标题。

### P2 主题收口（下一批）
- 四个 tab 统一天空底 + 白色大卡 + 橙色主操作；
- `app.json` tabBar `selectedColor` 从 `#4285F4` 改 `#ff9a1f`（现蓝色与首页橙主题打架）；
- 注意：`assets/tab/*.png` 现为蓝色系图标，改选中色后需评估是否重出图标（或用 CSS 无法改 PNG 颜色）。

## 三、验收与风险

- 静态：`check-wxss` / `check-taps` / `structure-check` / `syntax-check-all` 必须全绿；
- 入口：`tests/unit/index-entries.test.js` 只守首页；P1 改关卡页/玩法页后需补同类守卫（入口方法丢失会静默无反应）；
- E2E：`--module=pages` 真机渲染回归；全量回归等你说"上线"再跑；
- 风险最高的是「题型 chips 收进二级分段」：会改变老用户找"自由练"的路径，需要一次切换引导或保留搜索式入口；
- 学习页数据卡依赖接口，游客态要有「-」占位（现有 `.state-chip` 已有先例）。

### 复查中发现并顺手修掉的两个问题

1. **玩法线 chip 进度显示 `x/10`**：`level.js` 里复用了页面级的 `LEVELS_PER_GRADE`（10 关，自由练口径），
   而玩法线是 30 关。已改用 `challenge.LEVELS_PER_GRADE`，截图确认变成 `0/30`，进度卡也回到 `0/90`。
2. **自动滚到当前关会把学段 tab 滚出屏幕**：首版用 `offsetTop: -240`，结果首屏直接从进度卡开始。
   现在只在「当前关在第 8 行之后」才滚动，且不再传 offset —— 前几关一屏可见，不打扰。

### 实测高度（截图核对）

- 关卡页头部：游客态约 740rpx → 610rpx；登录态约 660rpx → 550rpx。
  **没有达到方案里估的 320rpx**，因为新增了「继续第 N 关」条（约 100rpx）并保留游客横幅 —— 
  换来的是「不用在 30 关里找关」，这笔交换比继续压头部更值。
- 玩法页首屏：可见卡片 4 张 → 6 张。

### 校验

- `node e2e/run-all.js --module=pages --no-e2e` → 5/5 PASS（syntax / structure / wxss / unit / taps）。
- `tests/unit/index-entries.test.js` 扩到 11 条断言：新增玩法页 / 关卡页 / 学习页 / 我的页的入口清单守卫，
  删入口即红。
