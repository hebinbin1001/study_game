# D · 黏土玩具 —— 落地规划

> 方向已于 2026-10-28 由用户拍板：**选 D（Claymorphism 软胶质感）**。
> 本文是执行规划，不含已完成的代码改动。每一步都可单独验收。

---

## 0. 一句话判断

**黏土化不是"换一套配色"，是"换一套阴影语法"。**

现在全站靠 `box-shadow: 0 12rpx 0 rgba(0,0,0,.18)` 这种「外部硬底边」撑塑料片质感。
黏土把这条硬边搬到元素**内侧**，再加一道内高光和一层外柔影——
形状还在、厚度还在、按压手感还在，只是从「硬塑料」变成「软胶」。

这决定了工程量：**不需要动布局、间距、字号、信息架构**。要动的是阴影，而阴影集中在两处：
全局组件（`app.wxss` 17 条）+ 页面级自定义（264 条）。

## 3. 黏土阴影配方（这一节是 D 的核心）

### 3.1 四档

```css
/* L1 小件：chip / badge / 小图标底 / 棋盘格 */
--clay-1:
  inset 0 -4rpx 0 rgba(20, 50, 90, .10),
  inset 0  3rpx 0 rgba(255, 255, 255, .45),
  0 3rpx 6rpx rgba(20, 50, 90, .10);

/* L2 常规：按钮 / 浅色面板 */
--clay-2:
  inset 0 -6rpx 0 rgba(20, 50, 90, .12),
  inset 0  5rpx 0 rgba(255, 255, 255, .50),
  0 6rpx 14rpx rgba(20, 50, 90, .12);

/* L3 主操作：主 CTA / 大面板 / 结算弹层 */
--clay-3:
  inset 0 -10rpx 0 rgba(20, 50, 90, .15),
  inset 0   8rpx 0 rgba(255, 255, 255, .55),
  0 14rpx 28rpx rgba(20, 50, 90, .16);

/* L0 白底卡片：白叠白看不出高光，靠「底内暗 + 落影」做软垫 */
--clay-card:
  inset 0 -8rpx 0 rgba(20, 50, 90, .07),
  0 8rpx 18rpx rgba(20, 50, 90, .10);
```

**为什么白卡要单独一档**：`inset 0 5rpx 0 rgba(255,255,255,.5)` 叠在白底上是纯白，零效果。
白卡的厚度只能靠内暗做，这是最容易踩的坑。

### 3.2 四态矩阵

| 态 | 阴影 | 位移 | 说明 |
|---|---|---|---|
| 默认 | `--clay-2` | 无 | |
| 按压 `:active` | 底部内暗 −6 → −2，落影 6 → 2 | `translateY(2rpx) scale(.98)` | **关键改动**：现方案 `translateY(6rpx)` 位移太大，按下时按钮"跳"，黏土靠"压扁"表达而非"下沉" |
| 禁用 `:disabled` | `inset 0 -3rpx 0 rgba(0,0,0,.06)`，去高光 | 无 | 配 `opacity: .55` + `filter: grayscale(.5)` |
| 加载 | 同禁用形状 + 文字替换为 `···` | 无 | 原生 `button` 可用 `loading` 属性，但样式不统一，建议自绘 |

### 3.3 批量替换正则（264 条页面级硬底边）

把
```css
box-shadow: 0 12rpx 0 rgba(0, 0, 0, 0.18), 0 20rpx 40rpx rgba(0, 0, 0, 0.12);
```
改成
```css
box-shadow: inset 0 -12rpx 0 rgba(20,50,90,.14), inset 0 4rpx 0 rgba(255,255,255,.45), 0 10rpx 20rpx rgba(20,50,90,.12);
```

规则：
1. 原 `0 Nrpx 0` 的 **N 原样搬到 `inset 0 -Nrpx 0`** —— 厚度不变，形状不变
2. 原第二条软影（`0 Arpx Brpx`）保留，色相统一成 `rgba(20,50,90,...)`
3. 自动插入内高光 `inset 0 4rpx 0 rgba(255,255,255,.45)`（白底元素跳过，改用 `--clay-card`）
4. 替换后用 `git diff` 逐文件抽查，重点看白底卡片

> 这一步**必须整站一次做完**。分成两批会出现「首页软的、关卡页硬的」，比现在更乱。

## 6. 待确认（3 项，需要你拍板后才动）

1. **页面背景要不要降饱和？**
   现 `#5aa9e6 → #a3d5ff → #d8efff` 饱和度偏高，黏土的柔和高光会被背景抢。
   建议降到 `#7fb9e3 → #b9dcf7 → #e3f2ff`（更浅、更灰、更柔）。
   **代价**：18 个「没自带背景色」的页面底色全变，需要截图回归。
   **不做也行**——黏土的手感主要来自阴影，不换背景也能成立，只是"软"得没那么明显。

2. **`--pri` 要不要从 `#ffb703` 改成 `#ff9a1f`？**
   `#ffb703` 偏黄，叠白色内高光后两者糊在一起，按钮会显得"没立体"。
   改成 `#ff9a1f` 高光和底色分得开。**代价**：所有橙色按钮会比现在深一档。

3. **`share-card` 的深色底保留吗？**
   它和 `AGENTS.md §5`「统一浅色主题」直接冲突。保留就得给它单独做一整套深色文字/卡片配色 + 深色截图回归；不保留就改成浅色卡片。

## 8. 并发协作约定（2026-10-28 补，功能开发与 UI 重构并行时适用）

现状：工作区 206 个未提交改动（miniprogram 下 122 个），功能开发与本次重构在同一棵树上并行。

### 8.1 已实测的冲突面

| 冲突类型 | 是否会静默丢改动 | 本项目实测 |
|---|---|---|
| **整文件覆盖**（一方 Write 整个 wxss） | 会 | 批 3 改用**行级脚本替换**规避：只替换 `box-shadow` 声明行，其余字节不动 |
| **同行修改**（双方改同一个 class 的同一属性） | 会 | 无法自动规避，靠「改完立刻跑护栏 + 抽查 diff」暴露 |
| **新增裸色值 / 硬底边** | 不会，会被拦 | 已发生 1 次：`avatar.wxss` 被并行加了 `#c77c02`，护栏计数 38→39 当场报红，已顺手换 token |
| **重命名 class** | 会（选择器变死代码，无报错） | 唯一的高危操作，批 3 期间禁止 |

批 3 的 49 个目标 wxss 中，43 个近 1 小时无人改动；交集只有 6 个，且都是批 1/批 2 自己改的。

### 8.2 分工

- **功能侧**：`.js` / `.wxml` / `.json` 随意改，与批 3 天然分离。
- **UI 侧**：批 3 只改 `.wxss`，且只改阴影 / 圆角 / 按钮尺寸三类声明。
- 功能侧若需在 49 个目标页里新增**带阴影的卡片或按钮**，先告知——直接给 token 写法（`box-shadow: var(--clay-2)`），否则批 3 收口后又要重开一轮。
- **禁止重命名 class**：批 3 期间任何 wxml 改类名都会让对应 wxss 选择器失效，且不会有任何报错。

### 8.3 提交流程（这才是最大的实际风险）

不是「互相覆盖」，而是**回滚连坐**：批 3 是一次性改 49 个文件，如果出问题要 `git checkout`，会把功能侧正在做的改动一起带走。

所以：

1. 批 3 开始**前**，把已完成的功能改动提交一次（哪怕 message 写 `wip:`）；
2. 批 1 + 批 2 单独一次提交（护栏先落地）；
3. 批 3 单独一次提交，出问题只回滚这一个 commit，功能改动不受影响。

### 12.3 这一批自己踩的两个坑（都补了护栏）

**坑 1：批量脚本偏移算错 2 个字符，520 处字号声明被写坏。**

`normalize-font.js` 里 `valStart` 取在属性名之后（即冒号处），而正则给的 `vm.index` 是
相对「冒号 + 空格之后」的偏移，于是 `replace` 从冒号开始吃掉 5 个字符：

```
font-size: 40rpx   →   font-size48rpxpx
```

这在 CSS 里不是语法错误，是「未知属性」—— 浏览器丢掉整条声明，页面不报错、
括号配对正常、截图里只是某些字变小了。**而 `check-wxss.js` 当时只扫 `pages/`，
520 处里有 300 多处落在 `pkg-games/`，护栏完全看不见。**

修法：`font-size` 与数字都还在字符串里，用 `font-size(\d{2})rpxp?x?` 无损还原 520 处，
一行没丢。护栏补两条：
  - `check-wxss.js` 的扫描范围从「app.wxss + pages」改成「miniprogram 下全部 60 个 wxss」；
  - 新增第 7 条规则：块内不允许「字母紧接数字+rpx」（`font-size24rpxpx` 这种粘连写法），
    负值 `-6rpx` 与 `translate(10rpx)` 不会误报。

教训：**批量改写脚本必须自己验证幂等性**（连跑两次第二次应为 0 处），
并且**改完要有一条能看见「声明被吃掉」的断言**，光靠「括号配对 + 单元测试」不够。

**坑 2：整段渐变替换把令牌定义本身替换成了自引用。**

自动贴脚形、不新增节点、不改布局。

**但要如实记一笔**：这不是「台座」，只是脚下一圈柔影。真正的台面（一块椭圆台盘）
仍然要等真机 —— 静态截图判断不了它会不会挡靴子。
