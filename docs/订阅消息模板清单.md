| 有，且里面能选到教育类模板 | 一次同意、终身可发，不受额度限制 | **告诉我**，方案要改（`pk_accept` 的按钮从「攒票动作」变成「一次性开关」，断档预警也不必担心额度） |

## 一、现在要申请的（1 个）

### M1 · 战帖被应战

| 项 | 值 |
|---|---|
| 环境变量 | `WX_TPL_PK_ACCEPT` |
| 业务触发 | 好友应战你的战帖、交完成绩的那一刻 |
| 收件人 | 战帖发起人 |
| 点击跳转 | `pages/pk/pk?code=XXXXXX`（直接看这局结果） |
| 实际模板标题 | `对战结果通知` |
| 实际后台搜索词 | `比赛结果`（一次性订阅） |
| 类目 | 信息查询 |

**需要的字段（3 个）**

| 序号 | 语义 | 类型 | 我们填什么 | 示例 |
|---|---|---|---|---|
| 1 | 比赛名称 | `thing` / `thing4` | 对手昵称，超 20 字截断 | `小明` |
| 2 | 对战结果 | `thing` / `thing3` | 对手比分 + 你的胜负 | `对手 8/10 题 · 你赢了` |
| 3 | 对战时间 | `time` / `time5` | 应战时间（东八区，HH:mm） | `22:35` |

**挑模板时的三个判断点**

1. **第 2 个字段的标签要中性**。填进去的是**对手**的分数，如果模板把它写成「您的成绩」「您的得分」，卡片就会明确地说错话。看到这种标签直接换一个。
2. **正文句式读一遍**。模板正文是固定的，只有 `{{thing1.DATA}}` 这类占位符能替换。如果句式是「{{thing1.DATA}} 已完成学习，用时 {{thing2.DATA}}」，塞进去会变成「小明 已完成学习，用时 对手 8/10 题」，那就换。
3. **标题别太跳**。「挑战通知」「互动提醒」最贴；实在没有，用「学习提醒」也能看，只是标题和内容略错位。

**找不到 3 个字段的模板怎么办**：`thing` + `date` 两个字段也能跑，把胜负那部分并进 `thing1`（如 `小明应战，你赢了`）。这种情况告诉我，我改 `build()`。

## 三、为什么不是一次申请 4 个

**订阅额度是按模板算的，不是按账号算的。**

`requestSubscribeMessage({ tmplIds: [...] })` 里，用户勾选的是「允许接收『学习提醒』这类消息」—— 每个模板单独计 1 条额度。不存在「用户同意了这个小程序」这种账户级总开关。

推论三条：

1. **一个模板只能发一种消息**，标题是模板自带的，改不了；
2. 想覆盖 4 个场景 = 4 个模板 = 用户要点 4 次同意；
3. 每多一个模板，就是多一次打扰。所以模板数量要按「用户真的会为了它点允许」来定，不是按「我想发多少种消息」来定。

现在只有 `pk_accept` 有发送渠道（事件驱动、零成本），其余三个连触发机制都还没有，先申请就是空转。

## 四、字段类型速查（写错就是 47003）

| 类型 | 上限 | 说明 |
|---|---|---|
| `thing` | **20 个字符** | 汉字、数字、字母、符号都行。注意是按**字符**不是字节，`对手 8/10 题 · 你赢了` 是 15 个字符，远没到上限 |
| `phrase` | **5 个汉字** | 只能是汉字，本项目用不到 |
| `date` | 年/月/日，可带 24 小时时间 | `2026年10月28日 22:35` 或 `2026-10-28` |
| `time` | 24 小时制 | `22:35` |
| `number` | 32 位数字 | 只能是数字 |
| `character_string` | 32 位 | 数字、字母、符号 |

传参时 key 必须带模板里的**序号**：`thing1` / `thing2` / `date3`。只写 `thing` 会报 47003，而且微信**不会告诉你哪个字段错了** —— 这就是为什么我要你截图字段列表。

## 六、申请完之后（我来做的三件事）

1. 把 `server/subscribe.js` 里 `pk_accept.build()` 的三个 key 改成后台的真实字段名；
2. 把模板 ID 填进云托管环境变量 `WX_TPL_PK_ACCEPT`（这个要你在控制台粘，粘完重新部署才生效）；
3. 在云托管「开放接口服务」白名单加一条 `POST /cgi-bin/message/subscribe/send`（不配也能跑，但会回落公网 https + 自己维护 access_token）。

联调步骤和错误码对照见 `docs/订阅消息接入指南.md` 第五、六节。最重要的一条先记住：

**`43101` 不是 bug。** 它的意思是「这个用户没有订阅额度了」。一次性订阅就是一张一张攒票，用户点一次允许只换一条。日志里遇到它只记一行 `console.log`，不重试——重试也发不出去。
